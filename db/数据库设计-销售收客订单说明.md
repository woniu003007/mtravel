# 销售收客订单表说明

本文件说明 `013_sales_booking_order_schema.sql` 中的销售收客订单主链路表。收客订单是团队下客户报名、游客名单、应收金额和后续计调履约、财务应收的来源。

## 设计原则

- 收客订单必须挂在正式团队 `sales_teams` 下，一个团队可以有多个订单。
- 页面按订单信息、行程说明、导游相关、客户信息、价格信息、酒店信息、附加说明、费用变更记录、游客名单分区保存。
- 订单、价格明细、游客名单和费用变更记录分表保存，避免把游客和价格挤进订单主表。
- 保存订单后刷新团队实收人数和剩余人数；取消订单不占用团队余位。
- 订单状态、价格类型、游客类型和费用变更状态均通过 `CHECK` 约束限制。
- 所有业务表带 `tenant_id`，查询和修改必须带租户边界。
- 业务数据默认软删除，普通删除不物理移除记录。

## 表清单

| 表名 | 作用 |
| --- | --- |
| `sales_orders` | 销售收客订单主表，保存客户、接送、行程、导游、酒店、人数、应收、已收、余额和订单状态。 |
| `sales_order_price_lines` | 订单价格明细表，保存成人、儿童、交通、酒店、门票、自费、附加费等收入分项。 |
| `sales_order_guests` | 订单游客名单表，保存游客证件、客户类型、分房、领队和身份证校验结果。 |
| `sales_order_fee_changes` | 订单费用变更记录表，保存加收、退减等应收调整记录。 |

## 关键字段

### `sales_orders`

| 字段 | 说明 |
| --- | --- |
| `team_id` | 所属销售团队 ID。 |
| `order_no` | 订单编号，同一租户下未删除订单唯一。 |
| `customer_id` / `customer_name` | 客户单位 ID 和名称快照。 |
| `contact_name` / `contact_phone` | 客户联系人和电话。 |
| `customer_team_no` | 客户方团队编号。 |
| `source_province` / `source_city` / `source_district` | 客源地。 |
| `travel_description` | 行程说明，保存来程、返程、参团时间等内容。 |
| `pickup_info` / `dropoff_info` / `pickup_remark` | 接站、送站和接送备注。 |
| `guide_name` / `guide_phone` / `guide_remark` | 导游相关信息。 |
| `hotel_info` | 酒店信息或住宿要求。 |
| `adult_count` / `child_count` / `child_no_bed_count` / `senior_count` / `escort_count` | 不同客人类型数量。 |
| `guest_count` | 订单总人数，保存时按游客名单和人数字段汇总。 |
| `receivable_amount` / `received_amount` / `balance_amount` | 应收、已收、余额。已收后续由收款模块回写。 |
| `fee_remark` / `confirm_remark` / `order_remark` | 费用说明、确认说明、订单备注。 |
| `status` | `pending` 未处理，`confirmed` 已确认，`cancelled` 已取消。 |

## 联动规则

- 新增或修改订单后，按未取消订单汇总团队 `used_seats`。
- `remaining_seats = total_seats - used_seats`，允许出现负数用于暴露超收问题。
- 订单应收按价格明细小计合计。
- 订单余额按应收减已收计算。
- AI 辅助录入只回填草稿，不自动保存订单、价格或游客名单。
- 拼团、转团、收款、电子合同、打印和费用变更审批后续在本表基础上继续扩展。
