# 销售收客订单表说明

本文件说明 `013_sales_booking_order_schema.sql` 中的销售收客订单主链路表。收客订单是团队下客户报名、游客名单、应收金额和后续计调履约、财务应收的来源。

## 设计原则

- 收客订单必须挂在正式团队 `sales_teams` 下，一个团队可以有多个订单。
- 页面按订单信息、行程说明、导游相关、客户信息、价格信息、酒店信息、附加说明、费用变更记录、游客名单分区保存。
- 订单主表只保存订单抬头、人数和汇总金额；订单原始价格和后续应收调整统一写入 `sales_order_charge_lines`。
- `sales_order_price_lines`、`sales_order_fee_changes` 为早期拆表结构，当前保留兼容和历史迁移，不再作为新代码读写来源。
- 保存订单后刷新团队实收人数和剩余人数；取消订单不占用团队余位。
- 订单状态、应收明细归类、游客类型和费用变更状态均通过 `CHECK` 约束限制。
- 所有业务表带 `tenant_id`，查询和修改必须带租户边界。
- 业务数据默认软删除，普通删除不物理移除记录。

## 表清单

| 表名 | 作用 |
| --- | --- |
| `sales_orders` | 销售收客订单主表，保存客户、接送、行程、导游、酒店、人数、应收、已收、余额和订单状态。 |
| `sales_order_charge_lines` | 订单应收明细表，统一保存原始订单价格和后续加收、退减等应收调整。 |
| `sales_order_guests` | 订单游客名单表，保存游客证件、客户类型、分房、领队和身份证校验结果。 |
| `sales_order_price_lines` | 早期订单价格明细兼容表，保留用于历史迁移和旧数据核对。 |
| `sales_order_fee_changes` | 早期费用变更兼容表，保留用于历史迁移和旧数据核对。 |

### `sales_order_charge_lines`

| 字段 | 说明 |
| --- | --- |
| `order_id` | 所属订单 ID。 |
| `team_id` | 所属团队 ID，便于团队维度统计和后续报表聚合。 |
| `line_kind` | 明细归类：`base_price` 原始订单价格，`adjustment` 后续应收调整。 |
| `line_type` | 业务分项类型，例如成人、儿童、附加费、酒店附加费、门票、自费等。 |
| `item_name` | 分项名称，用于页面展示和报表说明。 |
| `unit_price` / `quantity` / `amount` | 单价、数量、金额。原始价格行金额为单价乘数量，应收调整行按正负金额保存。 |
| `change_type` | 调整方向，`increase` 加收，`decrease` 退减；原始价格行为空。 |
| `fee_project_id` / `fee_project_name` | 费用项目 ID 和名称快照，应收调整行来自企业资料附加费用项目。 |

| `status` | `effective` 原始价格生效，`approved` 调整生效，`cancelled` 调整作废，另预留 `pending`、`rejected`。 |
| `registered_by` / `registered_at` | 登记人和登记时间。 |
| `sort_order` | 显示顺序，主要用于原始价格行。 |

## 联动规则

- 新增或修改订单后，按未取消订单汇总团队 `used_seats`。
- `remaining_seats = total_seats - used_seats`，允许出现负数用于暴露超收问题。
- 新增订单应收按 `sales_order_charge_lines.line_kind = 'base_price'` 的 `amount` 合计。
- 修改订单时重建 `base_price` 行，但保留 `adjustment` 历史流水；订单应收按原始价格合计加 `approved` 调整金额计算。
- 生效费用变更按 `line_kind = 'adjustment'` 且 `status = 'approved'` 汇总到订单应收；作废、驳回和待处理记录不计入应收。
- 费用变更统计按费用项目、变更方向、客户、团队、登记时间和登记人汇总，不使用变更方向承担原因分类。
- 真实收款不写入 `sales_order_charge_lines`，后续财务收款应单独设计收款记录和核销分配表，再回写订单已收和余额。
- 订单余额按应收减已收计算。
- AI 辅助录入只回填草稿，不自动保存订单、价格或游客名单。
- 拼团、转团、收款、电子合同、打印和费用变更审批后续在本表基础上继续扩展。
