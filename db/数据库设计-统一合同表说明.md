# 统一合同表设计说明

## 表作用

`contracts` 是系统统一合同台账。客户管理和采购管理中的“合同管理”使用同一张表和同一套接口，
通过 `contract_type` 区分分销商、景区、酒店、餐厅、车队、大交通、其它、地接、导游、
财务费用、现收现退、附加费用和购物合同。

## 关联规则

- 分销商合同使用 `customer_id` 关联客户单位。
- 常规采购合同使用 `supplier_id` 关联供应商。
- `customer_id` 和 `supplier_id` 不允许同时有值。
- 财务费用、现收现退、附加费用和其它等特殊合同允许只保存相对方名称快照。
- 合同甲乙方信息保存为快照，客户、供应商或企业资料后续变化不覆盖历史合同。

## 核心字段

| 字段 | 说明 |
| --- | --- |
| `id` | 合同主键，自增 bigint。 |
| `tenant_id` | 租户 ID，所有查询和修改必须带租户边界。 |
| `contract_type` | 合同业务类型，与合同管理页签一致。 |
| `customer_id` | 客户单位 ID，仅分销商合同使用。 |
| `supplier_id` | 供应商 ID，采购类合同使用。 |
| `contract_no` | 合同编号，同一租户内未删除记录唯一。 |
| `contract_name` | 合同名称。 |
| `counterparty_name` | 合同相对方名称快照。 |
| `start_date`、`end_date` | 合同有效期。 |
| `settlement_terms` | 结算方式或结算条款。 |
| `purchase_price_summary` | 采购价格摘要。 |
| `legal_subject`、`invoice_subject`、`settlement_subject` | 法律、开票和结算主体。 |
| `attachment_id`、`contract_file_url` | 主合同文件信息。 |
| `party_a_*`、`party_b_*` | 合同甲乙方信息快照。 |
| `agreement_content`、`other_content` | 合同主要约定和补充内容。 |
| `status` | `active` 正常、`disabled` 停用、`terminated` 提前终止。 |
| `is_deleted`、`deleted_at`、`deleted_by` | 软删除字段。 |

## 附件规则

公共附件统一使用：

- `business_module = '合同管理'`
- `business_type = '合同'`
- `business_id = contracts.id`

不再区分“客户销售合同”和“采购合同”两套附件类型。

## 迁移结果

`007_unified_contract_schema.sql` 负责建立统一表并迁移旧合同和附件；
核对合同数量、编号和附件绑定后，`008_drop_legacy_contract_tables.sql`
删除 `customer_contracts` 和 `supplier_contracts`。业务记录仍使用软删除。
