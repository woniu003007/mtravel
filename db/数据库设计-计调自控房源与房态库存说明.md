# 计调房源与房态库存退役说明

本文件说明 `009_dispatch_room_status_schema.sql` 的当前状态。

甲方已确认当前业务没有自营房源，也不需要独立的房态库存、房号、锁房流水模块。原 `计调操作 / 自控房源与房态库存` 模块已退役，前端菜单、后端接口和相关数据表均不再作为正式系统能力保留。

## 当前脚本作用

`009_dispatch_room_status_schema.sql` 现在是可重复执行的退役清理脚本，只负责删除历史房态相关表：

- `controlled_room_day_statuses`
- `controlled_room_lock_records`
- `room_inventories`
- `controlled_room_units`
- `controlled_room_types`
- `controlled_room_resources`

脚本不再创建任何房态或锁房表。

## 替代口径

- 酒店基础资料继续使用采购管理的 `hotel_resources`。
- 产品行程和直接创建团队中的“关联酒店”只从启用的采购酒店资源读取候选项。
- 正式团队安排中的住宿成本继续走 `dispatch_team_arrangements` 及其价格明细、订单归属和流程记录，不依赖房态库存表。
- 后续如果甲方重新提出酒店库存或排房能力，需要按采购酒店资源重新设计，不沿用已退役的自控房源模型。
