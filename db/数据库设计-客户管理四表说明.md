# 数据库设计：客户管理四表说明

本文档记录当前 PostgreSQL `mtravel` 数据库中客户管理模块已建立的 4 张基础表。  
四张表均采用多租户设计，业务表通过 `tenant_id` 区分不同地接公司。客户、合同等基础资料默认采用软删除，不直接物理删除记录。

## 1. tenants：租户 / 地接公司表

### 表作用

一条记录代表一家使用平台的旅游地接公司，用于区分不同公司的账号、权限和业务数据归属。后续客户、合同、订单、团队、财务等业务数据都通过 `tenant_id` 归属到具体公司。

### 字段说明

| 字段名 | 字段含义 |
| --- | --- |
| `id` | 租户主键 ID，系统内部使用。 |
| `tenant_code` | 租户编码，平台侧唯一识别一家地接公司，建议使用英文或数字编码。 |
| `tenant_name` | 租户名称，即地接公司名称。 |
| `status` | 租户状态。`active` 表示启用，`disabled` 表示停用。停用后该公司账号应禁止登录或限制业务操作。 |
| `contact_name` | 租户联系人姓名，通常是该地接公司的管理员或负责人。 |
| `contact_phone` | 租户联系人手机号或联系电话。 |
| `remark` | 租户备注，用于记录开通说明、合作信息或内部备注。 |
| `created_at` | 创建时间，记录租户开通时间。 |
| `updated_at` | 更新时间，记录租户资料最后修改时间，由触发器自动维护。 |
| `is_deleted` | 是否已删除。`false` 表示正常，`true` 表示已软删除。 |
| `deleted_at` | 删除时间。未删除时为空。 |
| `deleted_by` | 删除人账号或名称。未删除时为空。 |

## 2. customer_categories：客户分类表

### 表作用

用于维护客户分类字典，例如 A 类客户、B 类客户、旅行社、单位客户等，供客户主档、订单和统计模块使用。

### 字段说明

| 字段名 | 字段含义 |
| --- | --- |
| `id` | 客户分类主键 ID，系统内部使用。 |
| `tenant_id` | 租户 ID，标识该客户分类属于哪一家地接公司，实现多租户数据隔离。 |
| `category_name` | 客户分类名称，如 A 类客户、B 类客户、组团旅行社、单位客户等。 |
| `default_credit_limit` | 默认授信额度。新增或切换客户分类时可带入客户主档，客户保存后可单独调整。 |
| `sort_order` | 排序号，数字越小越靠前，用于下拉框和列表展示排序。 |
| `status` | 分类状态。`active` 表示启用，`disabled` 表示停用。停用后不建议再用于新增客户。 |
| `created_by` | 创建人名称或账号，记录是谁创建了该分类。 |
| `remark` | 分类备注，用于说明分类规则或内部管理口径。 |
| `created_at` | 创建时间，记录分类创建时间。 |
| `updated_at` | 更新时间，记录分类最后修改时间，由触发器自动维护。 |
| `is_deleted` | 是否已删除。`false` 表示正常，`true` 表示已软删除。 |
| `deleted_at` | 删除时间。未删除时为空。 |
| `deleted_by` | 删除人账号或名称。未删除时为空。 |

## 3. customers：客户单位表

### 表作用

用于维护下游客户、组团社、批发商、单位客户等客户主档，是订单、团队、应收账款、合同提醒和额度提醒的基础数据。

### 字段说明

| 字段名 | 字段含义 |
| --- | --- |
| `id` | 客户单位主键 ID，系统内部使用。 |
| `tenant_id` | 租户 ID，标识该客户属于哪一家地接公司，实现多租户数据隔离。 |
| `customer_code` | 客户编码或业务代码，同一租户内唯一。 |
| `customer_name` | 客户单位名称。 |
| `category_id` | 客户分类 ID，关联 `customer_categories`，用于区分 A 类客户、B 类客户、旅行社、单位客户等。 |
| `province` | 客户所在地省份。 |
| `city` | 客户所在地城市。 |
| `district` | 客户所在地区县。 |
| `department_name` | 归属部门名称冗余字段，用于列表展示和历史数据兼容。 |
| `dispatcher_name` | 默认操作计调姓名冗余字段，用于列表展示和历史数据兼容。 |
| `contact_name` | 客户负责人或联系人姓名。 |
| `contact_phone` | 客户负责人或联系人电话。 |
| `registrar_name` | 登记人名称。 |
| `contract_expire_date` | 客户合同有效期止，用于下单或排团时进行到期提醒。 |
| `status` | 客户主档状态。`active` 表示启用，`disabled` 表示停用。合同未签、即将到期、已过期不写入本字段，应由合同数据计算。 |
| `remark` | 客户备注，用于记录合作说明、特殊结算要求或内部备注。 |
| `created_by` | 创建人名称或账号，记录是谁创建了客户单位。 |
| `created_at` | 创建时间。 |
| `updated_at` | 更新时间，记录客户资料最后修改时间，由触发器自动维护。 |
| `is_deleted` | 是否已删除。`false` 表示正常，`true` 表示已软删除。 |
| `deleted_at` | 删除时间。未删除时为空。 |
| `deleted_by` | 删除人账号或名称。未删除时为空。 |
| `credit_limit` | 客户实际授信额度。默认可来自客户分类，但保存后按客户独立维护。 |
| `department_id` | 归属部门 ID，关联企业部门资料。为空表示全公司可见或暂未分配。 |
| `dispatcher_employee_id` | 默认操作计调员工 ID，关联企业员工资料。为空表示未分配。 |
| `settlement_method` | 客户结款方式。`unlimited` 表示不限，`cash` 表示现结，`monthly_1` 到 `monthly_12` 表示按 1 到 12 个月账期结款。 |
| `bill_start_date` | 客户账单起始日期，用于计算应收账期和结款提醒。 |
| `bill_day` | 客户约定结款日，取值 1 到 31；为空表示未约定固定结款日。 |

## 4. contracts：统一合同表（客户合同部分）

### 表作用

客户合同已并入统一 `contracts` 表。客户合同通过 `contract_type = 'customer'` 区分，
记录客户单位、合同期限、结算条款、甲乙方快照和合同文件，并支撑下单 / 排团合同有效期提醒。

### 字段说明

| 字段名 | 字段含义 |
| --- | --- |
| `id` | 合同主键 ID，系统内部使用。 |
| `tenant_id` | 租户 ID，标识该客户合同属于哪一家地接公司，实现多租户数据隔离。 |
| `customer_id` | 客户单位 ID，关联 `customers`。历史合同无法匹配客户时可为空，但新建合同应绑定客户。 |
| `contract_no` | 合同编号，同一租户内唯一。 |
| `contract_type` | 合同类型。客户合同固定为 `customer`。 |
| `counterparty_name` | 客户名称快照，用于保留合同签署时的原始抬头。 |
| `start_date` | 合同开始日期。 |
| `end_date` | 合同结束日期或有效期止，用于合同到期提醒。 |
| `settlement_terms` | 结款方式或结算条款，如月结、现结等。 |
| `contract_file_url` | 合同文件地址，用于保存合同扫描件、电子文件或外部文件链接。 |
| `status` | 合同管理状态。`active` 表示正常使用，`disabled` 表示停用，`terminated` 表示提前终止。合同自然到期应由 `end_date` 计算。 |
| `print_status` | 打印状态或打印标记。 |
| `legal_subject` | 客户合同主体，用于记录合同签署的法律主体。 |
| `invoice_subject` | 开票主体，用于记录发票抬头或开票责任主体。 |
| `settlement_subject` | 结算主体，用于记录应收结算归属主体。 |
| `template_name` | 合同模板名称。 |
| `reminder_days` | 到期提醒提前天数。 |
| `attachment_id` | 合同附件 ID，关联公共附件表。 |
| `party_a_name` | 甲方名称快照，通常为本企业名称，可从企业公司信息带入后手工调整。 |
| `party_a_phone` | 甲方联系电话快照。 |
| `party_a_fax` | 甲方传真号码快照。 |
| `party_a_address` | 甲方办公地址快照。 |
| `party_a_contact` | 甲方负责人或联系人快照。 |
| `party_b_name` | 乙方名称快照，通常为客户单位名称，可从客户主档带入后手工调整。 |
| `party_b_phone` | 乙方联系电话快照。 |
| `party_b_fax` | 乙方传真号码快照。 |
| `party_b_address` | 乙方地址快照。 |
| `party_b_contact` | 乙方负责人或联系人快照。 |
| `agreement_content` | 合同约定内容，用于记录双方核心合作约定。 |
| `other_content` | 合同其它内容，用于记录补充条款或未尽事项。 |
| `created_by` | 创建人账号或名称。 |
| `remark` | 合同备注，用于记录补充条款、特殊结算说明或内部备注。 |
| `created_at` | 创建时间。 |
| `updated_at` | 更新时间，记录合同最后修改时间，由触发器自动维护。 |
| `is_deleted` | 是否已删除。`false` 表示正常，`true` 表示已软删除。 |
| `deleted_at` | 删除时间。未删除时为空。 |
| `deleted_by` | 删除人账号或名称。未删除时为空。 |

## 删除策略

客户管理模块的基础资料建议默认软删除，不建议直接物理删除。

删除时更新字段：

| 字段名 | 更新规则 |
| --- | --- |
| `is_deleted` | 改为 `true`。 |
| `deleted_at` | 写入当前删除时间。 |
| `deleted_by` | 写入当前操作人账号或名称。 |

常规列表查询必须增加条件：

```sql
WHERE tenant_id = :tenant_id
  AND is_deleted = false
```

物理删除只建议用于测试数据清理、数据归档后的彻底清除，不能作为正常业务删除方式。

## 唯一约束策略

软删除后，业务唯一项只约束未删除记录。

| 表名 | 唯一项 | 规则 |
| --- | --- | --- |
| `customer_categories` | `tenant_id + category_name` | 同一家地接公司内，未删除的客户分类名称不能重复。 |
| `customers` | `tenant_id + customer_code` | 同一家地接公司内，未删除的客户编码不能重复。 |
| `contracts` | `tenant_id + contract_no` | 同一家地接公司内，未删除的合同编号不能重复。 |

主键 `id` 仍然全表唯一，不受软删除影响。`tenant_id + id` 保留唯一约束，用于保证关联数据不会跨租户串联。

## 状态字段策略

`status` 字段继续使用 `varchar`，但必须配合数据库 `CHECK` 约束，不能任意写值。

| 表名 | 允许值 | 说明 |
| --- | --- | --- |
| `tenants.status` | `active`、`disabled` | 租户是否启用。 |
| `customer_categories.status` | `active`、`disabled` | 客户分类是否启用。 |
| `customers.status` | `active`、`disabled` | 客户主档是否启用。 |
| `contracts.status` | `active`、`disabled`、`terminated` | 合同是否正常使用、停用或提前终止。 |

`customers.settlement_method` 使用固定枚举值，避免结款方式在业务规则中散落为手写文本。

| 值 | 说明 |
| --- | --- |
| `unlimited` | 不限。 |
| `cash` | 现结。 |
| `monthly_1` 至 `monthly_12` | 1 到 12 个月账期。 |

`customers.bill_day` 只允许为空或 1 到 31。具体月份不存在该日期时，后续账期计算应按业务规则处理到当月最后一天。

客户合同是否未签、即将到期、已经过期，不写入 `customers.status`。  
这些状态应通过合同表计算：

| 展示状态 | 判断方式 |
| --- | --- |
| 无有效合同 | 当前客户没有 `active` 合同。 |
| 即将到期 | 合同 `end_date` 距当前日期小于系统配置的提醒天数。 |
| 已过期 | 合同 `end_date` 小于当前日期。 |

这样可以避免一个 `status` 字段同时承担“客户是否启用”和“合同是否有效”两类含义。

## 授信额度字段策略

客户分类和客户单位分别保存额度字段，二者作用不同，不能混用。

| 表名 | 字段 | 规则 |
| --- | --- | --- |
| `customer_categories` | `default_credit_limit` | 分类默认授信额度，用于新增或切换客户分类时带入客户表单。 |
| `customers` | `credit_limit` | 客户实际授信额度，客户保存后按客户独立维护。 |

额度字段使用 `numeric(14,2)`，单位为元，数据库通过 `CHECK` 约束保证金额不能小于 0。  
修改客户分类默认额度不会自动覆盖已经保存的客户实际授信额度，避免覆盖人工调整结果。
