# 客户扩展、采购管理与公共附件表说明

本文件说明 `005_customer_purchase_expansion_schema.sql` 中新增和扩展的表结构。合同相关结构已经由
`007_unified_contract_schema.sql` 统一迁移到 `contracts`，本文件中的旧合同字段仅用于说明迁移来源。

## 设计原则

- 所有业务表均带 `tenant_id`，后端查询和修改必须按租户隔离。
- 业务删除统一使用软删除字段：`is_deleted`、`deleted_at`、`deleted_by`。
- `status` 或状态类字段使用 `varchar(20)`，并通过 `CHECK` 约束限定允许值。
- 金额字段使用 `numeric(14,2)`，并通过约束禁止负数。
- 常用查询索引均以 `tenant_id, is_deleted` 开头，减少多租户数据量增长后的扫描范围。
- 唯一约束采用部分唯一索引，只约束未删除记录。
- 附件首版使用本地磁盘存储，表里只保存文件元数据和相对访问地址。

## `common_attachments`

公共附件表用于统一管理上传文件。业务模块可先上传附件，再把 `attachment_id` 或 `file_url` 写入对应业务表。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `business_module` | 业务模块名称，例如客户管理、采购管理、财务管理。 |
| `business_type` | 业务类型，例如客户合同、采购合同、地接确认单。 |
| `business_id` | 业务记录 ID。先上传后绑定时允许为空。 |
| `original_filename` | 用户上传时的文件名。 |
| `stored_filename` | 系统保存到磁盘时的文件名。 |
| `storage_path` | 服务器本地存储路径。 |
| `file_url` | 前端访问或下载时使用的相对地址。 |
| `content_type` | 文件 MIME 类型。 |
| `file_size` | 文件大小，单位字节。 |
| `status` | `active` 可用，`disabled` 停用。 |
| `uploaded_by` | 上传人账号或名称。 |
| `created_by` | 创建人账号或名称。 |

约束：

- `tenant_id, id` 保持唯一，用于其它业务表按租户安全引用附件。

## `customer_credit_accounts`

客户授信账户表用于当前阶段的额度台账维护。首版支持手工维护已占用额度和审批中额度；订单确认、费用变更自动占用属于后续联动开发。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `customer_id` | 客户单位 ID。 |
| `credit_limit` | 授信额度。 |
| `occupied_amount` | 已占用额度。 |
| `pending_approval_amount` | 审批中额度。 |
| `available_amount` | 数据库生成列，等于授信额度减已占用额度和审批中额度。 |
| `warning_threshold` | 预警阈值。 |
| `over_limit_action` | 超限处理方式：`none` 不处理，`remind` 提醒，`approval` 转审批。 |

约束：

- 授信额度、已占用额度、审批中额度、预警阈值都不能小于 0。

## `purchase_resources`

旅游资源主档表用于维护全部可复用旅游资源，包含免费游览资源和需要采购的资源。资源主档只记录资源本身的信息，供应商绑定由 `purchase_relations` 管理。统一报价保存在采购关系，分类报价明细由 `supplier_resource_prices` 管理。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `resource_type` | 资源类型：`scenic` 景区，`hotel` 酒店，`restaurant` 餐厅，`shopping` 购物，`vehicle` 用车，`traffic` 大交通，`ground_agent` 地接，`other` 其它资源。 |
| `procurement_mode` | 默认采购属性：`required` 需要采购，`not_required` 无需采购。该值用于产品、团队引用资源时的默认建议，不用零报价推断免费。 |
| `resource_name` | 资源名称。 |
| `province` / `city` / `district` | 资源所在省、市、区县。 |
| `phone` | 联系电话。 |
| `contact_name` | 资源联系人，独立于供应商联系人。 |
| `fax` | 传真号码。 |
| `address` | 详细地址。 |
| `scenic_level` | 景区国家 A 级：`unrated` 未评级，`1a` 至 `5a` 对应 1A 至 5A；非景区为空。 |
| `star_level` | 酒店或餐厅星级/接待标准，从企业产品字典 `reception_standard` 选择；非酒店为空。 |
| `category_tags` | 类型标签。餐厅可保存菜系，购物可保存商品类别，大交通或其它资源可保存业务分类，多个值用英文逗号分隔。 |
| `longitude` / `latitude` | 高德地图 GCJ-02 经纬度，地点类资源必须成对维护；有有效坐标后才进入产品地图。 |
| `business_status` | 营业状态：`unmaintained` 未维护、`open` 营业中、`suspended` 暂停营业、`closed` 已停业。 |
| `opening_time` / `closing_time` | 每日营业开始和结束时间，必须成对维护，结束时间晚于开始时间。 |
| `site_visit_status` | 踩点状态：`unmaintained` 未维护、`not_visited` 未踩点、`visited` 已踩点。 |
| `last_site_visit_date` | 最近踩点日期；已踩点时必填且不能晚于当前日期，其他状态为空。 |
| `site_visit_note` | 踩点备注，用于记录现场考察结论和注意事项。 |
| `capacity` | 最大接待人数或容量，餐厅、购物等资源使用。 |
| `table_count` | 餐桌数量，仅餐厅资源使用。 |
| `meal_standard` | 团餐标准，例如“10人/桌，8菜1汤”；价格仍在供应商报价维护。 |
| `vehicle_type` / `seat_count` / `billing_mode` | 用车资源规格。计费模式为 `daily` 按天、`trip` 按趟次/行程、`distance_time` 按公里和时间。 |
| `service_area` / `reference_days` | 地接或大交通服务范围；地接可维护参考天数。 |
| `included_items` / `excluded_items` | 地接、大交通或其它服务类资源的包含和不包含内容。 |
| `resource_unit` | 其它资源默认计价单位。 |
| `warm_tip` | 温馨提示，用于记录预约、接待或注意事项。 |
| `introduction` | 资源简介。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 资源类型限定为景区、酒店、餐厅、购物、用车、大交通、地接、其它资源八类。
- 历史资源统一初始化为需要采购，避免将未知资源误判为免费；确认免费资源后可改为无需采购。
- 无需采购资源可继续用于产品行程、地图、产品方案和产品手册，但后续团队采购安排、成本和结算不应自动生成记录。
- 同一租户、同一类型、同一省市区县、同一资源名称的未删除记录不能重复。
- 景区必须维护国家 A 级；历史景区初始化为未评级，不推断真实业务信息。
- 地点类资源包括景区、酒店、餐厅、购物，可维护经纬度、营业状态、营业时间和踩点状态；历史地点类资源只补“未维护”状态，不推断真实营业和踩点信息。
- 经纬度必须同时为空或同时有值，经度范围为 -180 至 180，纬度范围为 -90 至 90。
- 营业开始和结束时间必须同时为空或同时有值，并只支持同一天内结束时间晚于开始时间的营业时段。
- 踩点状态为已踩点时必须填写不晚于当前日期的最近踩点日期；未维护或未踩点时最近踩点日期为空。
- 非地点类资源不保存经纬度、营业和踩点字段；类型切换时由后端清空不适用字段。
- 酒店和餐厅可保存星级；用车必须维护座位数；地接必须维护服务地区。
- 国家 A 级、营业状态和踩点状态分别建立仅覆盖未删除景区的租户级部分索引，用于资源总览筛选。
- 删除资源只做软删除，不直接物理移除。

边界说明：本节景区字段仅扩展统一资源主档 `purchase_resources`。`scenic_resources` 仍是独立的“景区 + 票种”模型，本次不建立关联、同步或双写关系。

## 资源资料与知识库

资源资料挂在统一资源主档 `purchase_resources` 下，景区、酒店、餐厅、购物、用车、大交通、地接和其它资源均可上传。
资料跟随资源主档，不跟随供应商或采购关系。原始文件复用 `common_attachments`，知识库状态、抽取文本和向量索引状态由
`knowledge_documents`、`knowledge_document_chunks` 和 `knowledge_processing_tasks` 维护。该链路不写入 `scenic_resources`，也不影响独立的“景区 + 票种”页面。

当前页面支持一次上传多个 `pdf/doc/docx/xls/xlsx/txt/jpg/jpeg/png/webp` 文件，并支持列表查看、原文件下载、发布、停用、处理失败重试和删除。上传事务提交后由独立小线程池异步处理，不在上传接口内同步等待 OCR 和向量化。Word、Excel、文本和有文本层的 PDF 优先本地抽取；图片和扫描 PDF 优先使用阿里云 OCR，失败时再使用已配置的百炼视觉能力兜底。文本切片通过百炼 `text-embedding-v4` 生成 1024 维向量后写入 PostgreSQL `pgvector`。

新上传资料默认允许作为后续《产品手册》的数据来源，但默认不开放知识库问答检索。当前只完成资料与向量底座，产品手册生成器、向量相似度检索接口和问答页面尚未开发。

### `knowledge_documents`

知识文档表是一份资源资料文件的业务状态记录。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `source_type` | 业务来源类型，采购资源资料使用 `purchase_resource`。 |
| `source_id` | 采购资源主档 ID，关联 `purchase_resources`。 |
| `attachment_id` | 公共附件 ID，关联原始上传文件。 |
| `file_sha256` | 文件内容 SHA-256 摘要，用于后续重复资料识别。 |
| `processing_status` | 处理状态：`pending` 待处理、`processing` 处理中、`succeeded` 成功、`failed` 失败、`deleted` 已删除。 |
| `review_status` | 审核状态：`draft` 草稿、`published` 已发布、`disabled` 已停用。 |
| `index_status` | 向量索引状态：`pending` 待向量化、`indexed` 已入库、`failed` 失败、`deleted` 已删除。 |
| `extracted_text` | 文件抽取或 OCR 后的正文文本。 |
| `index_version` | 索引版本号，删除或重试时递增，防止旧任务重新写入过期向量。 |
| `usage_product_manual` | 是否允许作为后续产品手册生成的数据来源。 |
| `usage_qa` | 是否允许作为后续知识库问答检索的数据来源。 |

约束：

- `source_type` 只允许 `purchase_resource`，避免其它业务误写入。旧值 `purchase_resource_scenic` 由 `029` 数据补丁迁移。
- `attachment_id` 必须来自同租户 `common_attachments`。
- `source_id` 必须来自同租户 `purchase_resources`；后端会校验该资源存在且未删除。
- 同一附件只能对应一条未删除知识文档。

### `knowledge_document_chunks`

知识文档切片表保存可检索的文本片段和向量。`embedding` 使用 `vector(1024)`，与当前规划的百炼 embedding
维度保持一致。未配置 embedding 服务时，允许先保存文本切片但不写向量，文档保持待向量化状态。

删除资源资料文件时，本表按 `tenant_id + document_id` 物理删除切片记录，确保对应向量立即从检索数据中消失。
文档和附件元数据仍采用软删除，便于后续审计。

### `knowledge_processing_tasks`

知识文档处理任务表记录抽取文本、OCR 和向量化任务状态。任务带 `index_version`，后台处理前必须确认任务版本仍等于
文档当前版本，且文档未删除、未停用。删除资料时，后端会把未完成任务置为 `cancelled`，防止异步任务在删除后重新写入向量。

## `resource_projects`

资源费用项目表用于维护不同资源类型下可选择的项目类型。采购关系的价格管理会按资源类型过滤该表，例如景区只显示成人、儿童、免票等项目，酒店只显示标间、大床房等项目。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `resource_type` | 资源类型：`scenic` 景区、`hotel` 酒店、`restaurant` 餐厅、`vehicle` 车队、`traffic` 大交通、`other` 其它、`misc` 杂费、`ground_agent` 地接、`extra_fee` 附加费用、`shopping` 购物。数据库仍兼容导游、财务费用、现收现退、票务等历史分类，但费用项目页面不作为主 tab 展示。 |
| `project_name` | 项目名称，例如成人、儿童、标间、标准餐。 |
| `statistics_enabled` | 是否纳入统计。 |
| `sort_order` | 排序号。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 同一租户、同一资源类型、同一项目名称的未删除记录不能重复。
- 删除只做软删除，不直接物理移除。
- 启用的座位数报价规则会自动补齐同名车队费用项目，例如 `60座`。该同步只新增或启用项目，不自动删除或重命名旧项目，保证历史采购价格和团队安排明细可追溯。

初始化项目：

- 景区：成人、儿童、学生、老人、优待、免票、60周岁、套票。
- 酒店：标间、大床房、三人间、加床、房券、单房差、早餐。
- 餐厅：标准餐、豪华餐、餐券、围桌餐、自助餐。
- 车队：座位数项目来自启用的座位数报价规则，例如 7座、19座、33座、45座；另保留车费、司机补贴、司机餐补、停车费、过路停车费、其它等通用费用项目。早期的 5座轿车、7座商务车、19座中巴、33座大巴、45座大巴描述型种子已停止作为初始化项目使用。
- 大交通：高铁票、普通火车票、机票、船票、订票服务费。
- 其它：旅游意外险、会务服务费、综合服务费。
- 杂费：矿泉水、旅游帽、胸牌、行李牌、横幅。
- 地接：地接综合费、地接服务费、当地交通费、当地住宿费、当地餐费。
- 附加费用：加景点、升级住宿、加餐、延住、超公里费、超时费。
- 购物：乳胶、茶叶、翡翠、厨具、黄金饰品、丝绸、珍珠。

## `purchase_relations`

采购关系表用于表达“某个资源由哪个供应商供给，以及达到多少成团数量后适用这组价格”。统一报价直接保存在关系表，只有分类报价的项目明细放在 `supplier_resource_prices`。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `resource_type` | 资源类型。 |
| `resource_id` | 资源 ID，关联采购资源主档。 |
| `resource_name` | 资源名称。 |
| `supplier_id` | 供应商 ID。 |
| `group_quantity` | 成团数量。0 表示散团同价，大于 0 表示达到该数量后适用对应关系价格。 |
| `is_default` | 是否为当前资源的默认供应商。同一资源未删除记录最多只能有一个默认供应商。 |
| `price_mode` | 报价模式。`unified` 表示当前绑定按一个统一金额报价，`classified` 表示按费用项目分别报价。 |
| `unified_price` | 关系级统一报价金额，仅 `unified` 模式使用。 |
| `price_remark` | 统一报价的适用条件、有效范围或补充说明。 |
| `status` | `active` 有效，`disabled` 停用，`expired` 过期。 |

兼容字段：

- `purchase_price`、`price_unit`、`settlement_method`、`valid_from`、`valid_to`、`priority_level` 为历史兼容字段，当前页面和接口不再作为主操作字段。

资源页提供“新增供应商并绑定”快捷入口。该入口仍写入 `suppliers`、`purchase_relations`
和 `supplier_resource_prices`，不会新增重复供应商报价表，也不会影响资源资料。供应商分类由后端按资源类型固定。
统一报价只写入 `purchase_relations.unified_price`，不生成费用项目明细；分类报价按用户选择的费用项目逐条写入 `supplier_resource_prices`。两种模式不允许同时保存金额，切换模式时后端在同一事务内清理另一种模式的数据。
未删除的采购关系受数据库约束保护：`unified` 必须有非负的统一报价，`classified` 必须不保存关系级统一报价。已软删除的历史关系保留原始快照，不因新约束被改写。

## `purchase_resource_optional_items`

资源级自费项目主档挂在统一资源主档下，用来维护同一资源下可反复复用的自费项目名称和类型。它只保存项目主档本身，不保存供应商成本，也不保存产品最终对外价。供应商报价和产品设计分别在采购关系和产品快照表中维护。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `resource_id` | 所属资源主档 ID。 |
| `project_name` | 自费项目名称，例如游船、电瓶车、景交车。 |
| `item_type` | 项目类型：`scenic_transport` 景区小交通，`recommended_self_pay` 推荐自费。 |
| `price_unit` | 计价单位，固定为 `yuan_per_person`。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 同一资源下未删除的自费项目名称不能重复。
- 计价单位固定为元/人，不支持按趟、按天或其它单位。
- 历史采购关系自费报价可回填到该主档，便于同一项目名称在多个供应商和多个介绍版本中复用。

## `purchase_relation_optional_items`

采购关系自费项目报价表用于维护某个景区资源供应商能够提供的多个自费项目。报价页由业务人员直接填写项目名称：后端会复用当前景区同名主档，不存在时在同一事务内自动创建主档，再通过采购关系绑定到具体供应商；它不会被混入普通成人、儿童等分类报价。产品设计选择后使用项目的最终对外价生成产品 Word，供应商成本价和建议对外价只用于内部成本参考。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `relation_id` | 采购关系 ID。 |
| `resource_optional_item_id` | 资源级自费项目主档 ID。历史数据允许为空，新增记录应关联对应主档。 |
| `project_name` | 自费项目名称，例如游船、电瓶车。 |
| `cost_price` | 供应商成本价，固定按元/人。 |
| `suggested_sale_price` | 供应商建议对外价，固定按元/人，仅作为产品设计默认值。 |
| `price_unit` | 计价单位代码，固定为 `yuan_per_person`。 |
| `price_description` | 自费项目价格说明。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 自费项目只允许在景区资源供应商绑定中维护；报价页无需选择或新建主档，后端以手填名称自动复用或创建当前景区主档。
- `resource_optional_item_id` 不应指向其它资源类型的项目主档。
- 同一采购关系下未删除的自费项目名称不能重复。
- 成本价不能小于 0，计价单位固定为元/人。
- 删除或编辑移除项目只做软删除；资源供应商整组更新在同一事务内软删除旧项并批量保存新项。

## `purchase_relation_ticket_templates`

采购关系游客名单模板表用于维护“景区资源 + 供应商/票务渠道”对应的游客名单 Excel 模板。模板配置挂在采购关系下，不挂在供应商全局，也不挂在景区资源全局，因为同一个景区在不同票务渠道可能使用不同模板。

关键字段：

| 字段 | 说明 |

## 删除策略

以上业务表均不做常规物理删除。删除操作只更新：

- `is_deleted = true`
- `deleted_at = now()`
- `deleted_by = 当前操作人`

列表、详情、更新、删除都必须带 `tenant_id` 和 `is_deleted = false` 过滤条件。

## 后续联动范围

本批表先完成基础维护能力。以下联动暂不在本批自动实现：

- 订单确认后自动占用客户额度。
- 收款后自动释放客户额度。
- 销售下单时自动校验客户产品授权。
- 票务下单时自动选择景区资源和票务模板。
- 按模板映射生成不同票务渠道的游客名单 Excel。
- 自动登录外部票务系统、自动下单和订单状态回传。
