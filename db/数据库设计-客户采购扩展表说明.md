# 客户扩展、采购管理与公共附件表说明

本文件说明 `005_customer_purchase_expansion_schema.sql` 中新增和扩展的表结构。合同相关结构已经由
`007_unified_contract_schema.sql` 统一迁移到 `contracts`，本文件中的旧合同字段仅用于说明迁移来源。

## 设计原则

- 所有业务表均带 `tenant_id`，后端查询和修改必须按租户隔离。
- 业务删除统一使用软删除字段：`is_deleted`、`deleted_at`、`deleted_by`。
- `status` 或状态类字段使用 `varchar(20)`，并通过 `CHECK` 约束限定允许值。
- 金额字段使用 `numeric(14,2)`，并通过约束禁止负数。
- 常用查询索引均以 `tenant_id, is_deleted` 开头，减少多租户数据量增长后的扫描范围。
- 唯一约束采用部分唯一索引，只约束未删除记录。
- 附件首版使用本地磁盘存储，表里只保存文件元数据和相对访问地址。

## 表清单

| 表名 | 作用 |
| --- | --- |
| `common_attachments` | 公共附件表，保存合同文件、确认单、票据、截图等附件元数据。 |
| `customer_credit_accounts` | 客户授信账户表，维护授信额度、已占用额度、审批中额度和可用额度。 |
| `customer_product_authorizations` | 客户产品授权表，维护客户可销售或可下单的产品范围。 |
| `suppliers` | 供应商表，维护酒店、景区、车队、餐厅、地接社等供应商档案。 |
| `purchase_resources` | 采购资源总览表，维护景区、酒店、餐厅和购物等资源主档。 |
| `resource_projects` | 资源费用项目表，维护不同资源类型下的项目类型。 |
| `purchase_relations` | 采购关系表，维护资源与供应商之间的绑定关系和成团数量。 |
| `supplier_resource_prices` | 供应商资源价格表，维护采购关系下不同项目类型的门市、同行和团队价格。 |
| `purchase_relation_ticket_templates` | 采购关系游客名单模板表，维护景区资源与供应商渠道对应的游客名单 Excel 模板。 |
| `purchase_relation_ticket_template_fields` | 采购关系游客名单模板字段映射表，维护 Excel 模板列与系统游客字段的对应关系。 |
| `hotel_resources` | 酒店资源表，维护酒店档案、房型、供应商和采购/协议价格。 |
| `scenic_resources` | 景区资源表，维护景区档案、票种、供应商、价格和免票半票规则。 |
| `ground_agents` | 地接外委表，维护地接社档案、外委任务、预算和确认单。 |

旧 `customer_contracts`、`supplier_contracts` 已迁移并删除，当前合同结构见
`数据库设计-统一合同表说明.md`。

## `common_attachments`

公共附件表用于统一管理上传文件。业务模块可先上传附件，再把 `attachment_id` 或 `file_url` 写入对应业务表。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `business_module` | 业务模块名称，例如客户管理、采购管理、财务管理。 |
| `business_type` | 业务类型，例如客户合同、采购合同、地接确认单。 |
| `business_id` | 业务记录 ID。先上传后绑定时允许为空。 |
| `original_filename` | 用户上传时的文件名。 |
| `stored_filename` | 系统保存到磁盘时的文件名。 |
| `storage_path` | 服务器本地存储路径。 |
| `file_url` | 前端访问或下载时使用的相对地址。 |
| `content_type` | 文件 MIME 类型。 |
| `file_size` | 文件大小，单位字节。 |
| `status` | `active` 可用，`disabled` 停用。 |
| `uploaded_by` | 上传人账号或名称。 |
| `created_by` | 创建人账号或名称。 |

约束：

- `tenant_id, id` 保持唯一，用于其它业务表按租户安全引用附件。

## `customer_credit_accounts`

客户授信账户表用于当前阶段的额度台账维护。首版支持手工维护已占用额度和审批中额度；订单确认、费用变更自动占用属于后续联动开发。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `customer_id` | 客户单位 ID。 |
| `credit_limit` | 授信额度。 |
| `occupied_amount` | 已占用额度。 |
| `pending_approval_amount` | 审批中额度。 |
| `available_amount` | 数据库生成列，等于授信额度减已占用额度和审批中额度。 |
| `warning_threshold` | 预警阈值。 |
| `over_limit_action` | 超限处理方式：`none` 不处理，`remind` 提醒，`approval` 转审批。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 同一租户下，一个未删除客户只能有一条授信账户。
- 授信额度、已占用额度、审批中额度、预警阈值都不能小于 0。

## `purchase_resources`

采购资源总览表用于维护采购侧资源主档。资源主档只记录资源本身的信息，供应商绑定由 `purchase_relations` 管理，具体价格由 `supplier_resource_prices` 管理。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `resource_type` | 资源类型：`scenic` 景区，`hotel` 酒店，`restaurant` 餐厅，`shopping` 购物。 |
| `resource_name` | 资源名称。 |
| `province` / `city` / `district` | 资源所在省、市、区县。 |
| `phone` | 联系电话。 |
| `fax` | 传真号码。 |
| `address` | 详细地址。 |
| `warm_tip` | 温馨提示，用于记录预约、接待或注意事项。 |
| `introduction` | 资源简介。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 资源类型限定为景区、酒店、餐厅、购物四类。
- 同一租户、同一类型、同一省市区县、同一资源名称的未删除记录不能重复。
- 删除资源只做软删除，不直接物理移除。

## `resource_projects`

资源费用项目表用于维护不同资源类型下可选择的项目类型。采购关系的价格管理会按资源类型过滤该表，例如景区只显示成人、儿童、免票等项目，酒店只显示标间、大床房等项目。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `resource_type` | 资源类型：`scenic` 景区、`hotel` 酒店、`restaurant` 餐厅、`vehicle` 车队、`traffic` 大交通、`other` 其它、`misc` 杂费、`ground_agent` 地接、`extra_fee` 附加费用、`shopping` 购物。数据库仍兼容导游、财务费用、现收现退、票务等历史分类，但费用项目页面不作为主 tab 展示。 |
| `project_name` | 项目名称，例如成人、儿童、标间、标准餐。 |
| `statistics_enabled` | 是否纳入统计。 |
| `sort_order` | 排序号。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 同一租户、同一资源类型、同一项目名称的未删除记录不能重复。
- 删除只做软删除，不直接物理移除。
- 启用的座位数报价规则会自动补齐同名车队费用项目，例如 `60座`。该同步只新增或启用项目，不自动删除或重命名旧项目，保证历史采购价格和团队安排明细可追溯。

初始化项目：

- 景区：成人、儿童、免票、60周岁、套票。
- 酒店：标间、大床房、三人间、加床、房券、单房差、早餐。
- 餐厅：标准餐、豪华餐、餐券、围桌餐、自助餐。
- 车队：座位数项目来自启用的座位数报价规则，例如 7座、19座、33座、45座；另保留车费、司机补贴、司机餐补、停车费、过路停车费、其它等通用费用项目。早期的 5座轿车、7座商务车、19座中巴、33座大巴、45座大巴描述型种子已停止作为初始化项目使用。
- 大交通：高铁票、普通火车票、机票、船票、订票服务费。
- 其它：旅游意外险、会务服务费、综合服务费。
- 杂费：矿泉水、旅游帽、胸牌、行李牌、横幅。
- 地接：地接综合费、地接服务费、当地交通费、当地住宿费、当地餐费。
- 附加费用：加景点、升级住宿、加餐、延住、超公里费、超时费。
- 购物：乳胶、茶叶、翡翠、厨具、黄金饰品、丝绸、珍珠。

## `purchase_relations`

采购关系表用于表达“某个资源由哪个供应商供给，以及达到多少成团数量后适用这组价格”。关系表不再直接承载具体价格，价格明细放在 `supplier_resource_prices`。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `resource_type` | 资源类型。 |
| `resource_id` | 资源 ID，关联采购资源主档。 |
| `resource_name` | 资源名称。 |
| `supplier_id` | 供应商 ID。 |
| `group_quantity` | 成团数量。0 表示散团同价，大于 0 表示达到该数量后适用对应关系价格。 |
| `status` | `active` 有效，`disabled` 停用，`expired` 过期。 |

兼容字段：

- `purchase_price`、`price_unit`、`settlement_method`、`valid_from`、`valid_to`、`priority_level` 为历史兼容字段，当前页面和接口不再作为主操作字段。

## `supplier_resource_prices`

供应商资源价格表用于维护采购关系下不同项目类型的价格。页面入口来自采购关系行内的“价格管理”。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `relation_id` | 采购关系 ID。 |
| `resource_project_id` | 资源费用项目 ID。 |
| `project_name` | 项目名称快照。 |
| `market_price` | 门市价。 |
| `peer_price` | 同行价。 |
| `team_price` | 团队价。 |
| `price_description` | 价格说明。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 同一采购关系、同一费用项目的未删除价格记录不能重复。
- 金额不能小于 0。
- 删除只做软删除，不直接物理移除。

## `purchase_relation_ticket_templates`

采购关系游客名单模板表用于维护“景区资源 + 供应商/票务渠道”对应的游客名单 Excel 模板。模板配置挂在采购关系下，不挂在供应商全局，也不挂在景区资源全局，因为同一个景区在不同票务渠道可能使用不同模板。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `relation_id` | 采购关系 ID。 |
| `template_name` | 模板名称，便于业务人员识别。 |
| `attachment_id` | 模板附件 ID。 |
| `template_file_url` | 模板文件访问地址快照。 |
| `original_filename` | 原始上传文件名快照。 |
| `sheet_name` | Excel 工作表名称。 |
| `header_row` | 表头行号，从 1 开始。 |
| `data_start_row` | 游客数据开始行号，必须大于表头行。 |
| `status` | `active` 启用，`disabled` 停用。 |

约束：

- 同一租户、同一采购关系只能有一条未删除模板配置。
- 模板附件必须来自同租户公共附件。
- 首版只维护模板和映射，不保存票务系统账号密码，不自动登录外部票务系统。

## `purchase_relation_ticket_template_fields`

采购关系游客名单模板字段映射表用于记录 Excel 模板列的填充方式。后续生成景区游客名单 Excel 时，系统会按该配置把游客姓名、证件号码、手机号等字段写入模板，也可以自动生成序号、写固定值或保留模板原内容。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `template_id` | 游客名单模板 ID。 |
| `template_header` | Excel 模板表头名称。 |
| `column_index` | Excel 列序号，从 1 开始。 |
| `system_field` | 系统游客字段编码。填充方式为 `tourist_field` 时使用，可选 `tourist_name`、`certificate_type`、`certificate_no`、`mobile`、`gender`、`birthday`、`remark`。 |
| `fill_mode` | 填充方式：`tourist_field` 游客字段，`sequence` 自动序号，`constant` 固定值，`keep_original` 不填充并保留模板原内容。 |
| `fixed_value` | 固定值填充内容，仅 `fill_mode = constant` 时使用。 |
| `required` | 是否必填。 |
| `sort_order` | 排序号。 |

约束：

- 同一模板下，同一列号只能有一条未删除映射。
- 系统字段和填充方式通过 `CHECK` 约束限定，避免任意字符串落库。
- `序号` 可配置为自动序号；`票型名称`、`证件类型`、`组团社` 等可配置为固定值；景区模板内原有说明、合并备注等可配置为不填充。

## `ground_agents`

地接外委表用于维护外委地接社和外委任务。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `ground_agent_name` | 地接社名称。 |
| `city` | 地接社所在城市或外委目的地。 |
| `task_name` | 外委任务名称。 |
| `itinerary_requirement` | 行程要求或服务要求。 |
| `total_budget` | 外委总预算。 |
| `confirmation_attachment_id` | 确认单附件 ID。 |
| `confirmation_file_url` | 确认单文件地址。 |
| `status` | `active` 进行中，`disabled` 停用，`completed` 已完成。 |

## 删除策略

以上业务表均不做常规物理删除。删除操作只更新：

- `is_deleted = true`
- `deleted_at = now()`
- `deleted_by = 当前操作人`

列表、详情、更新、删除都必须带 `tenant_id` 和 `is_deleted = false` 过滤条件。

## 后续联动范围

本批表先完成基础维护能力。以下联动暂不在本批自动实现：

- 订单确认后自动占用客户额度。
- 收款后自动释放客户额度。
- 销售下单时自动校验客户产品授权。
- 票务下单时自动选择景区资源和票务模板。
- 按模板映射生成不同票务渠道的游客名单 Excel。
- 自动登录外部票务系统、自动下单和订单状态回传。
