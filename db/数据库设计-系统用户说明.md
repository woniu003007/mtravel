# 数据库设计：系统用户表说明

## 表作用

`system_users` 用于保存每个租户的后台登录账号、密码哈希、当前角色和账号状态。该表是登录认证、操作留痕、租户隔离和后续权限控制的基础。

员工业务资料保存在 `enterprise_employees`。员工管理创建账号时，会把 `system_users` 与员工资料关联；登录认证仍只读取 `system_users`，避免员工资料异常影响基础登录链路。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `id` | 系统用户主键 ID，系统内部使用。 |
| `tenant_id` | 租户 ID，标识该用户属于哪一家地接公司。 |
| `username` | 登录账号，同一租户内未删除账号必须唯一。 |
| `password_hash` | 登录密码哈希，使用安全哈希算法保存，不能保存明文密码。 |
| `real_name` | 用户姓名，用于页面显示、操作日志和业务单据留痕。 |
| `mobile_phone` | 用户手机号，可用于联系、登录验证或后续消息通知。 |
| `email` | 用户邮箱，可用于通知或后续找回密码。 |
| `role_id` | 企业角色 ID，用于关联账号当前归属的业务角色。 |
| `employee_id` | 企业员工 ID，用于关联账号对应的员工资料。 |
| `role_code` | 角色编码。用于登录令牌和粗粒度权限识别，具体角色资料由企业角色表维护。 |
| `is_tenant_admin` | 是否租户管理员。`true` 表示该账号可维护本租户基础设置。 |
| `status` | 账号状态。`active` 表示启用，`disabled` 表示停用，`locked` 表示锁定。 |
| `last_login_at` | 最后登录时间。 |
| `remark` | 备注，用于记录账号管理说明。 |
| `created_by` | 创建人账号或名称。 |
| `created_at` | 创建时间。 |
| `updated_at` | 更新时间，由触发器自动维护。 |
| `is_deleted` | 是否已删除。`false` 表示正常，`true` 表示已软删除。 |
| `deleted_at` | 删除时间。未删除时为空。 |
| `deleted_by` | 删除人账号或名称。未删除时为空。 |

## 角色编码初始化

| 角色编码 | 说明 |
| --- | --- |
| `admin` | 管理员。 |
| `sales` | 销售。 |
| `dispatch` | 计调。 |
| `finance` | 财务。 |
| `boss` | 老板或经营管理者。 |

后续允许在企业角色表中新增业务角色。`role_code` 不再通过数据库 CHECK 固定为以上五项，由角色管理服务负责查重和有效性校验。

## 约束与索引

| 名称 | 作用 |
| --- | --- |
| `chk_system_users_status` | 限定账号状态只能为 `active`、`disabled`、`locked`。 |
| `uk_system_users_tenant_username_active` | 同一租户下未删除账号不能重复。 |
| `idx_system_users_tenant_deleted_status` | 按租户、软删除和状态查询账号。 |
| `idx_system_users_tenant_deleted_role` | 按租户、软删除和角色查询账号。 |
| `idx_system_users_tenant_deleted_employee` | 按租户、软删除和员工 ID 查询账号。 |

## 登录规则

- 登录时按 `tenant_id + username + is_deleted=false` 查询用户。
- 只有 `status=active` 的账号允许登录。
- 密码必须使用哈希校验，不能保存或比对明文密码。
- 登录成功后继续使用 Redis 在线会话和 JWT，不在数据库保存登录态。
- 菜单权限、按钮权限、数据范围权限由企业角色权限表维护，不混入本表。
- 员工停用或删除时，业务服务会同步处理关联账号状态，避免离职或停用人员继续登录。
