# 数据库设计：系统操作日志表说明

## 表作用

`system_operation_logs` 用于记录用户访问接口、维护资料、审核、导入导出和异常访问等操作。该表服务于后台审计、问题排查、安全追踪和客户现场问题复盘。

本表是多租户业务表，必须通过 `tenant_id` 区分不同地接公司的日志数据。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `id` | 操作日志主键 ID，系统内部使用。 |
| `tenant_id` | 租户 ID，标识该操作日志属于哪一家地接公司。 |
| `operator_id` | 操作人用户 ID。未登录或无法识别时为空。 |
| `operator_name` | 操作人账号或名称。未登录时可记录为 `anonymous` 或 `system`。 |
| `module_name` | 模块名称，例如客户管理、销售管理、财务管理、系统设置。 |
| `operation_type` | 操作类型，例如查询、新增、修改、删除、启用、停用、审核、导入、导出、登录、退出。 |
| `request_path` | 请求路径，不包含域名。 |
| `request_method` | 请求方法。系统统一使用 `GET` 和 `POST`。 |
| `request_params` | 请求参数摘要。密码、Token 等敏感字段必须脱敏。 |
| `ip_address` | 客户端 IP 地址。 |
| `user_agent` | 浏览器或客户端 User-Agent 摘要。 |
| `success` | 操作是否成功。`true` 表示成功，`false` 表示失败。 |
| `duration_ms` | 接口处理耗时，单位毫秒。 |
| `error_message` | 失败原因摘要。成功时为空。 |
| `created_at` | 操作发生时间。 |

## 接口日志规则

- `GET` 接口默认记录为 `查询`。
- `POST` 接口按路径或注解识别为 `新增`、`修改`、`删除`、`启用`、`停用`、`审核`、`导入`、`导出` 等操作类型。
- 敏感字段不能记录明文，包括 `password`、`token`、`Authorization`、`accessToken`、`refreshToken`。
- 日志采集失败不能影响业务接口正常返回。
- 普通查询日志后续可以通过配置关闭，但第一阶段先统一记录，便于开发期排查。

## 索引说明

| 索引 | 作用 |
| --- | --- |
| `idx_system_operation_logs_tenant_created` | 按租户和时间倒序查询日志。 |
| `idx_system_operation_logs_tenant_module_created` | 按租户、模块和时间查询日志。 |
| `idx_system_operation_logs_tenant_operator_created` | 按租户、操作人和时间查询日志。 |
| `idx_system_operation_logs_tenant_success_created` | 按租户、成功失败状态和时间查询日志。 |
