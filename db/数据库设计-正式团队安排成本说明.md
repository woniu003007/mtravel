# 正式团队安排成本表说明

本文件说明 `016_dispatch_team_arrangement_schema.sql` 中的正式团队安排成本表族。该表族承接团队执行阶段的大交通、住宿、用车、景区、用餐、其它、自费、购物、地接和附加费用，不替代订单应收、真实收款、供应商付款和导游结算表。

## 设计原则

- 产品团队安排是模板，正式团队安排是执行成本；产品排期批量生成团队时，只把产品模板复制为团队安排快照。
- 从产品模板复制来的安排默认是团队公共成本，`allocation_scope=team`，不关联订单。
- 产品排期复制模板不自动生成导游报账或计调审核流水；真实团队安排页面人工保存时，才按 `no_guide_report` 规则进入流程。
- 成本归属必须支持团队公共成本、单订单归属、多订单均摊，后续才能统计团队总成本、订单毛利和客户成本。
- 现结、挂账、预付在成本表中只表达成本结算方式，不代表客户真实收款。客户实际收款后续必须进入收款记录和收款分摊表。
- 本表族是后续应付、付款、导游报账、计调审核、财务审核、资源采购统计和利润统计的上游来源之一。

## 表清单

| 表名 | 作用 |
| --- | --- |
| `dispatch_team_arrangements` | 正式团队安排成本主表，保存团队、资源类型、供应商、日期、金额、报账状态和审核状态。 |
| `dispatch_team_arrangement_price_lines` | 安排价格明细表，保存费用项目、单价、数量、小计、现结、挂账、销售价、成本价、提成和返佣。 |
| `dispatch_team_arrangement_order_allocations` | 成本订单归属表，保存团队公共成本、单订单归属和多订单均摊拆分结果。 |
| `dispatch_team_arrangement_flow_records` | 下游流程流水表，保存无需导游报账时自动同步的导游报账、计调审核等流水。 |

## 关键字段

### `dispatch_team_arrangements`

| 字段 | 说明 |
| --- | --- |
| `team_id` / `team_no` | 所属正式团队 ID 和团队编号快照。 |
| `arrangement_type` | 资源类型：`traffic` 大交通，`hotel` 住宿，`vehicle` 用车，`scenic` 景区，`meal` 用餐，`other` 其它，`optional` 自费，`shopping` 购物，`ground_agent` 地接，`extra_fee` 附加。 |
| `allocation_mode` | 成本归属模式：`group_order_average` 表示团队公共或单订单归属，`multi_order_average` 表示多订单均摊录入来源。 |
| `split_mode` / `split_batch_no` | 多订单均摊方式和拆分批次号，用于追溯同一次录入拆出的多条成本。 |
| `supplier_id` / `supplier_name` | 供应商 ID 和名称快照，用于应付、采购资源和供应商维度统计。 |
| `settlement_type` | 默认结算类型：`cash` 现结，`credit` 挂账，用于团队安排和产品模板复制后的回显。 |
| `meal_type` / `fund_included` | 餐型、用餐时间、酒店早餐类型及基金是否包含等分类专用信息。 |
| `confirmed` / `confirmation_no` | 资源确认状态和确认号，例如酒店订房确认。 |
| `guide_id` / `guide_name` | 分类安排可关联导游的 ID 和姓名快照。 |
| `total_amount` | 安排合计金额。 |
| `cash_amount` | 现结金额。现结表示现场付款，需要后续进入导游报账、付款来源或备用金核销口径。 |
| `credit_amount` | 挂账金额。挂账进入供应商应付口径。 |
| `no_guide_report` | 是否无需导游报账。为 true 时表示跳过导游手工报账并自动同步导游报账和计调审核流水。 |
| `cost_stage` | 成本阶段：排团、导游报账、计调确认、财务审核。首版保存团队安排时为 `arrangement`。 |
| `guide_report_status` / `operator_audit_status` / `finance_audit_status` | 导游报账、计调审核和财务审核状态。 |

### `dispatch_team_arrangement_price_lines`

| `cash_amount` / `credit_amount` | 明细级现结和挂账金额。 |
| `sale_price` / `cost_price` | 自费、购物等混合收入成本项目使用。 |

| `head_fee_amount` / `consumption_amount` | 人头费和消费金额，主要用于购物、自费等统计。 |

### `dispatch_team_arrangement_order_allocations`

| 字段 | 说明 |
| --- | --- |
| `allocation_scope` | `team` 表示团队公共成本，`order` 表示归属到具体订单。 |

## 成本归属规则

### 团队公共成本

`全团/订单均摊` 选择 `=不关联订单=` 时，保存一条主成本和一条 `allocation_scope=team` 的归属记录。这笔成本计入团队总成本，不直接计入某个订单成本。

### 单订单归属

`全团/订单均摊` 选择某个订单时，保存一条主成本和一条 `allocation_scope=order` 的归属记录，整笔成本归属到该订单，用于订单毛利和客户成本统计。

### 多订单均摊

多订单均摊只允许新增，不直接编辑已拆分记录。保存时要求价格信息只有一条，系统按选中的订单拆成多条单订单成本记录：

- `by_order`：按订单数量平均拆分。
- `by_people`：按各订单人数比例拆分。

每条拆分记录保留同一个 `split_batch_no`，归属表中保存 `original_amount` 和 `allocation_amount`，用于财务追溯拆分来源。

## 导游报账同步规则

`no_guide_report` 不是导游付款或导游垫付的含义，而是表示这笔成本不需要导游手工报账。规则如下：

| 场景 | 业务含义 | 系统处理 |
| --- | --- | --- |
| 不勾选 + 现结 > 0 | 导游或现场人员需要参与报账，可能来自备用金或个人垫付。 | 进入导游报账流程，后续补付款来源和凭证。 |
| 不勾选 + 挂账 > 0 | 通常不是导游垫钱，但可能需要导游确认或补报凭证、消费、提成、返佣信息。 | 进入导游报账流程，但不默认计入导游个人垫付。 |
| 勾选 + 现结 = 0 | 导游不参与手工报账，系统自动同步导游报账和计调审核流水。 | 写入 `sync_source=no_guide_report` 的自动同步流水，主表状态置为 `synced`。 |
| 勾选 + 现结 > 0 | 业务冲突。现结需要付款来源和核销凭证，不能同时跳过导游报账。 | 前后端拦截保存。 |

只有 `sync_source=no_guide_report` 自动同步流水的安排，视为录入时的系统同步结果，录错后允许删除安排并同步软删除自动流水。已进入人工导游报账、计调审核或财务审核流程的安排不允许直接删除，应通过后续作废、冲销或调整记录处理。

## 产品排期复制规则

产品批量排期生成正式团队时，会把 `sales_product_arrangement_items` 和价格明细复制为正式团队安排快照：

- 复制团队、资源类型、日期、供应商、资源、金额和价格明细。
- 默认 `allocation_mode=group_order_average`，并写入一条 `allocation_scope=team` 的团队公共归属。
- 默认 `no_guide_report=false`、`guide_involved=true`、导游报账和计调审核状态为 `pending`。
- 不自动创建导游报账和计调审核流水，避免模板阶段的预计安排直接变成已确认执行数据。

人工直接创建团队时，首版不自动预填产品模板安排。后续如增加“选择产品模板复制安排”，应复用同一复制规则。

## 财务和统计支撑

本表族支撑以下统计维度：

- 团队总成本：按 `team_id` 汇总生效安排。
- 订单成本和订单毛利：通过 `order_allocations` 按订单归属汇总。
- 供应商应付：按 `supplier_id`、`credit_amount`、资源类型和业务日期统计。
- 资源采购统计：按 `arrangement_type`、`supplier_id`、`cost_stage` 和业务日期统计。
- 团队进度统计：按导游报账、计调审核、财务审核状态统计。
- 自费、购物和返佣统计：读取销售价、成本价、消费金额、人头费、公司返佣和导游提成字段。

真实客户收款、供应商付款、银行现金账、发票、导游备用金和导游结算仍需独立表族，不应写入本表族。

## 索引方向

- `tenant_id, is_deleted, team_id, arrangement_type, business_date`：团队安排页和团队成本汇总。
- `tenant_id, is_deleted, supplier_id, business_date`：供应商应付和资源采购统计。
- `tenant_id, is_deleted, operator_employee_id, business_date`：团队进度和计调工作量统计。
- `tenant_id, is_deleted, cost_stage, guide_report_status, operator_audit_status, finance_audit_status`：报账、审核和流程进度统计。
- `tenant_id, is_deleted, split_batch_no`：多订单均摊来源追溯。

## 模块边界

- 正式团队安排页已按同一表族接入大交通、住宿、用车、景区、用餐、其它、自费、购物、地接和附加费用的保存、修改、删除和列表展示。
- 所有分类共用订单归属、单订单归属、多订单均摊、无需导游报账同步和现结冲突校验规则，不再另建各自独立成本表。
- 本表族不直接处理供应商付款、客户收款和发票；这些流程需要在财务模块建独立表并通过团队、订单、供应商和成本来源关联。
