# 产品设计工作台资源编排重构设计

**状态：** 已根据当前确认的业务口径形成开发基线

**范围：** 销售产品设计工作台的资源选择、每日编排、全程用车、供应商成本快照、地图、报价与产品 Word 输出。

## 1. 目标与边界

把当前以“普通日资源列表”为中心的产品设计工作台，收敛为一个可以连续编排资源的工作台：地图或资源列表负责选择候选资源，右侧按明确的业务位置展示已安排资源，供应商与成本在加入时生成可追溯快照。

本次只改产品设计工作台，不改采购资源主档录入页、不改交通（航班/高铁/船）编排、不修改正式团队安排的既有业务流程。

以下内容不进入当天地图或每日资源：

- 用车/车队：属于产品级“全程用车”，可有多段，但不归属某一天，也不出现在地图候选中。
- 大交通：不纳入本工作台。

## 2. 已确认的业务模型

### 2.1 产品级：全程用车

全程用车是一组产品级安排，而不是 D1、D2 各复制一条资源。每条安排保存车辆资源、供应商采购关系、车型、起止天、数量、单价、成本和备注的快照；成本只在产品总成本中计算一次。

现有 `sales_product_arrangement_items` 虽然已支持 `vehicle`，但其保存服务仅面向 `product_scope='template'` 的正式产品。产品设计从 `design_draft` 开始，不能直接复用该服务，否则会把草稿与正式团队安排耦合。因此本设计新增产品设计专用的全程用车快照表与窄接口。

### 2.2 每日：四个固定区域

| 区域 | 资源类型 | 数量和排序规则 |
| --- | --- | --- |
| 当天住宿 | 酒店 | 0-N 家；同一天同一酒店不可重复；可排序 |
| 当天用餐 | 餐厅 / 酒店含早 | 早餐、中餐、晚餐各一个槽位；中晚餐至多一家餐厅 |
| 当日行程 | 景区、购物店、其它 | 一个顺序列表；同一天同资源默认不可重复 |
| 地接服务 | 地接 | 0-N 条；允许同一资源同日多次安排；独立排序 |

`sales_product_day_resources.arrangement_role` 是每日区域的唯一权威归属：

| 值 | 允许资源类型 | 说明 |
| --- | --- | --- |
| `accommodation` | `hotel` | 当晚实际入住的酒店 |
| `breakfast` | `restaurant` | 外部早餐餐厅 |
| `lunch` | `restaurant` | 中餐餐厅 |
| `dinner` | `restaurant` | 晚餐餐厅 |
| `itinerary` | `scenic`、`shopping`、`other` | 当日对客行程顺序 |
| `ground_service` | `ground_agent` | 内部地接服务顺序 |
| `unassigned` | `restaurant` | 只兼容历史数据；新建不得使用 |

历史 `vehicle` / `traffic` 日资源不做破坏性迁移，以兼容读取；新接口明确拒绝继续新增到每日资源中。

### 2.3 早餐是前一晚住宿的后续结果

早餐不再由当天酒店推断。

- D1 默认无酒店早餐来源；可显式安排外部早餐餐厅。
- Dn 的酒店早餐来自 Dn-1 的住宿酒店，且只统计勾选 `hotel_breakfast_included=true` 的酒店。
- 多酒店时，每家酒店独立维护“含次日早餐”。
- Dn 存在外部早餐餐厅时，D n-1 不允许再保留含次日早餐的酒店；反过来也一样。
- 删除或取消最后一家含次日早餐酒店后，D n 早餐自动变为“未安排”，除非已有外部早餐餐厅。

底层事实仍保存在“酒店标记”和“早餐餐厅角色”两处；后端统一计算 `BreakfastPlan` 返回给前端和 Word 服务，前端不得自行用不同算法推导。冲突切换必须由一个后端事务完成，不能先删一边、再写另一边。

## 3. 供应商与成本快照

### 3.1 加入资源

需要采购的资源在加入时按以下顺序选择采购关系：

1. 启用的默认采购关系，且供应商启用、报价可计算；
2. 其他启用且报价可计算的采购关系；
3. 没有可用报价时，仍允许加入，但保存为“待询价”：供应商和成本为空/0，不阻塞行程编排。

快照必须保存 `supplier_relation_id_snapshot`、供应商 ID/名称、报价模式、单价、数量和成本。只保存供应商 ID 不足以回溯同一供应商的不同采购关系和报价规则。

“可计算报价”定义为：供应商启用、采购关系启用；统一报价有非空金额，或分类报价至少有一条启用价格行。`purchase_relations.valid_from/valid_to` 不作为当前报价有效性依据。

### 3.2 更换供应商

右侧已安排资源仅显示紧凑文案：`供应商名称 · 成本 ¥X · 更换`。点击“更换”展开小型 `Popover`，只显示该资源合格的采购关系；不出现任意全局供应商。

选择后调用单条资源更新接口。后端在一个事务中重新校验关系、刷新所有成本快照、刷新兼容的自费项目采购引用，并重新计算工作台总成本/成人报价成本。资源主档之后变化不能反向更改已安排产品。

## 4. 地图与资源选择

### 4.1 一致的点击规则

地图气球标记、紧凑地图列表、全屏资源列表的点击行为完全一致：

| 点击资源 | 行为 |
| --- | --- |
| 酒店 | 直接追加到“当天住宿” |
| 景区、购物、其它 | 直接追加到“当日行程”末尾 |
| 地接 | 直接追加到“地接服务”末尾，允许重复 |
| 餐厅（已从右侧餐次槽位进入选择） | 直接写入该早餐/中餐/晚餐槽位 |
| 餐厅（无餐次上下文） | 打开仅含“早餐 / 中餐 / 晚餐”的小选择器，选定后立即写入 |

加入成功后：已安排资源所在区块滚动到可见位置并短暂高亮；该地图点和两种资源列表显示“已安排”状态。没有坐标的资源仍出现在资源列表且可点击加入。

不再保留重复的“加入 Dn”按钮，也不让地图点击只做高亮而不加入。

### 4.2 地图样式和容错

紧凑地图和全屏地图必须共用同一个“热气球 + 资源名称”标记 HTML/CSS 生成器，不再分别用 `designer-map-label` 与 `resource-map-label`。标记有普通、选中、已安排三种状态；密集区域启用聚合，插件不可用时降级为普通点位。

全屏地图维持全视口布局，右侧候选列表收窄为约 280–300px、行高约 48–52px。关闭时销毁地图、聚合器和 resize 定时器。地图失败时资源列表继续可用。

## 5. 前端页面结构

`designer.vue` 只承担数据加载、资源选择命令和页面编排；每日四块 UI、供应商选择器、产品级用车区、地图标记工具拆成独立组件，避免继续扩大单文件。

右侧每日布局固定为：

```text
当天住宿       [酒店卡片 ...]                 [+ 选择酒店]
当天用餐       [早餐] [中餐] [晚餐]           [各槽位选资源]
当日行程       景区 / 购物 / 其它可拖拽列表    [+ 从地图选择]
地接服务       独立可拖拽列表                  [+ 从地图选择]
```

餐次槽位不使用右侧抽屉：点击“选资源”只建立当前餐次上下文并把视觉焦点交给地图/资源列表；地图直接点餐厅但没有上下文时才弹出极小餐次选择器。产品级“全程用车”位于天切换区域之外，点击新增/编辑使用与系统一致的标准 Modal。

## 6. 接口契约

保留既有接口，新增/调整的核心契约如下：

```text
POST /sales/product/designer/day-resource/save
  + supplierRelationId?: number
  + replaceBreakfastSource?: boolean
  arrangementRole: accommodation | breakfast | lunch | dinner | itinerary | ground_service

POST /sales/product/designer/day-resource/reorder
  productId, dayNo, arrangementRole, dayResourceIds

POST /sales/product/designer/day-resource/supplier
  productId, dayResourceId, supplierRelationId

GET  /sales/product/designer/vehicle-resources
POST /sales/product/designer/vehicle-arrangement/save
POST /sales/product/designer/vehicle-arrangement/delete
POST /sales/product/designer/vehicle-arrangement/reorder
```

`GET /detail` 新增：每日 `mealPlan`、产品级 `vehicleArrangements`、`dayResourceCostAmount`、`vehicleCostAmount`。现有 `totalCostAmount` 改为两者之和，字段名保持不变以兼容当前报价区域。

## 7. 文档与报价

- 总成本和成人报价成本由后端重新汇总：每日资源成本 + 产品级全程用车成本。
- Word 行程表中的住宿显示当天全部酒店名称；早餐优先显示外部早餐餐厅，否则显示 Dn-1 实际勾选含早的酒店名称，最后才是“未安排”。
- 中餐、晚餐显示对应餐厅；地接不混入对客行程路线。
- Word 另增加“全程用车”汇总文本，只有存在用车安排时输出，不显示内部成本。

## 8. 数据库迁移与发布约束

当前线上 `mtravel` 实际的餐次唯一索引仍将 `accommodation` 纳入范围，导致多酒店被数据库拒绝。必须先执行已创建的 `052_sales_product_designer_multi_hotel_accommodation.sql`，并用索引谓词核验不再包含 `accommodation`。

随后新增 `053_sales_product_designer_resource_arrangement_v2.sql`，用于角色扩展、采购关系快照、产品级全程用车表、约束和索引。数据库变更只在用户再次确认目标为当前 `mtravel` 数据库后执行；本地基础 SQL、README 和设计说明必须同步。

后端代码变更生效必须重新编译、重启 Java 服务并检查 `/actuator/health`；Vite 热更新不能代替该步骤。

## 9. 本期验收规则

1. 同一天可保存两家以上酒店，数据库、详情、页面与 Word 都正确显示。
2. D2 早餐只从 D1 标记含早的酒店继承；外部早餐与酒店含早互斥。
3. 酒店、餐厅、景区、购物、其它、地接从地图/列表点击后都进入正确区块；地接可重复添加。
4. 用车只在产品级区域，不能出现在地图和每日资源；成本只计一次。
5. 加入资源默认带入有效默认供应商和成本快照；更换供应商后刷新成本、总成本和成人报价成本。
6. 全屏与紧凑地图的热气球标记、资源名称、选中态、已安排态一致；关闭再打开无重复点位或地图实例。
7. 无坐标、空结果、资源加载失败、地图失败、无有效供应商、历史未分配餐厅都具备明确且不阻断编排的反馈。

## 10. 固定假设与后置项

本期固定：中餐和晚餐各只支持一家餐厅；景区/购物/其它同一天不重复；D1 不承接行前夜酒店早餐；地接仅用现有资源、备注与排序表达；产品级用车从一开始支持多条安排。

后置：一餐多餐厅、地接时间/联系人等结构化字段、跨天资源使用提示、行前夜住宿、按酒店拆分早餐人数和更复杂的用车分段分摊。
