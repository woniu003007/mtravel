# 旧系统财务统计菜单调研与表设计依据

本文件用于约束后续财务、订单应收、收付款、成本、发票、冲抵和经营统计相关表设计。后续设计表结构前必须先阅读本文件，避免只按当前页面或本地文档推断。

## 调研范围

本次调研基于旧系统真实页面，覆盖 `财务管理` 和 `数据统计` 两组菜单。旧系统中部分统计页是入口页，需要继续进入下级统计页或扩大日期范围后才能看到真实数据。

### 财务管理菜单

| 菜单 | 旧系统作用 | 对表设计的影响 |
| --- | --- | --- |
| 团队审核 | 按团队展示应收、预算成本、实际成本、自费加点、购物消费、导服费、团队毛利和流程进度。 | 团队财务状态、审核状态、收入成本利润必须能按团队汇总。 |
| 团队预付款 | 按供应商、团号、费用说明展示预算成本、预付、已付、余款和付款入口。 | 预付款应属于付款/应付链路，不能放入订单收入明细。 |
| 银行现金账 | 展示收支日期、银行、收付款单位、收入、支出、余额、摘要、经办人、登记人、销账状态。 | 真实现金流必须有独立银行现金流水表。 |
| 应收帐款 | 按客户单位汇总收客数、应收、已收、余款。 | 应收需要客户维度汇总，来源可以是订单收入明细，已收来自收款分摊。 |
| 应收账款明细 | 按订单展示客户、收客数、业务员、下单人、应收、已收、余款、审核和收款入口。 | 订单应收和收款记录必须能按订单对账。 |
| 应付帐款 | 按供应商汇总现付、现付已付、挂账、挂账已付、余款。 | 应付需要区分现付和挂账。 |
| 应付账款明细 | 按供应商成本行展示付款单、类型、团号、费用说明、现付、挂账、已付、余款和付款入口。 | 成本/应付明细必须独立建表，并支持付款分摊。 |
| 成本明细预览 | 展示成本阶段、团队阶段、供应商、费用说明、现付、挂账、余款、导游、计调。 | 成本必须记录阶段，例如排团、导游、计调、财务审核。 |
| 导游备用金 | 展示团号、导游、计调、合计现付、备用金、企业码额度和申领详情。 | 导游备用金是独立资金链路，不应混入订单收入。 |
| 导游结算 | 展示备用金、导游现付、导游收入、导游上交、现收现退、财务费用、代收团款、结算余额和收付款入口。 | 导游结算需要独立结算表，并可关联收款和付款。 |
| 购物返佣 | 展示购物店、人数、人头费、消费总额、佣金、应收、已收、余款。 | 购物返佣是特殊应收，不能和普通客户订单价格混淆。 |
| 收款记录 | 展示团号、方式、项目、收款日期、付款单位/账户、备注、收款金额、经办人、登记人。 | 真实收款必须落在收款记录和收款分摊表，不是价格表。 |
| 付款记录 | 展示团号、方式、项目、付款日期、收款单位/账户、备注、付款金额、经办人、登记人。 | 真实付款必须落在付款记录和付款分摊表。 |
| 发票记录 | 展示开票时间、团号、客户、发票抬头、开票方、订单已收、发票金额、发票号码。 | 客户开票记录独立建表，并关联订单/客户/收款状态。 |
| 付款发票明细 | 展示供应商、费用说明、付款金额、发票已收和票据。 | 供应商票据和客户发票不是同一类数据。 |
| 财务收支进度 | 汇总订单应收、供应商应付、导游结算、购物应收、欠收和欠付。 | 统计需要同时读取应收、应付、导游结算、购物返佣、收付款分摊。 |
| 应收应付冲抵 | 维护供应商与采购商客户之间的关联，用于应收应付冲抵。 | 需要独立冲抵关系和冲抵流水，不能只靠客户或供应商主表字段。 |

### 数据统计菜单

| 菜单 | 旧系统作用 | 对表设计的影响 |
| --- | --- | --- |
| 团队进度统计 | 按操作计调统计团队安排、导游报账、计调审核、财务审核完成情况。 | 团队流程状态和审核状态必须可按计调、日期统计。 |
| 收客统计 | 按客户、地区、业务员、操作计调、产品等维度统计人数、成人、儿童、全陪、销售金额。 | 订单和游客名单必须保留客户、地区、业务员、计调、产品、客人类型。 |
| 利润统计 | 按团队/订单统计订单收入、加点利润、购物返佣、实际成本、导服费、利润、提成。 | 利润不能只看订单价格，必须组合收入、应收变更、成本、返佣、导服费和收款状态。 |
| 资源采购[排团] | 统计排团阶段资源采购，例如交通、酒店、供应商、资源项目。 | 成本明细需要 `cost_stage=arrangement` 或等价字段。 |
| 资源采购[导游] | 统计导游报账阶段购物、自费等资源采购。 | 成本明细需要 `cost_stage=guide` 并保留导游维度。 |
| 资源采购[计调] | 统计计调确认阶段酒店、导游相关、餐补等成本。 | 成本明细需要 `cost_stage=operator` 并保留计调维度。 |
| 资源采购[财务] | 统计财务审核阶段财务费用、购物等数据。 | 成本明细需要 `cost_stage=finance` 或审核状态。 |
| 账款统计 | 按客户/供应商/收款项目/付款项目统计应收、应付、收款、付款。 | 收付款项目和分摊对象必须标准化。 |
| 导游统计 | 统计导游带团数、天数、客人数、购物消费、自费销售、提成、导游收入。 | 导游维度需要贯穿团队、游客、购物、自费、结算。 |
| 收款汇总统计 | 按方式、项目、收款日期、单位、账户、金额、收款人、登记人汇总。 | 收款记录表必须保留方式、项目、账户、经办人、登记人和日期。 |
| 付款汇总统计 | 按方式、项目、付款日期、单位、账户、金额、付款人、登记人汇总。 | 付款记录表必须保留方式、项目、账户、经办人、登记人和日期。 |
| 报表中心 | 导出客户订单明细、团队费用成本明细、团队挂账成本明细。 | 报表字段反推收入、应收变更、成本分类、挂账成本必须能拆分。 |

## 报表中心字段依据

旧系统报表中心不是普通列表页，是导出中心。已确认三个导出均返回真实 `.xls` 数据。

- 客户订单明细字段包括：团号、团队类型、导游、客户、省份、订单金额、应收变更、订单总金额、人数、天数。
- 团队费用成本明细字段包括：团号、团队类型、导游姓名、销售金额、自费挂账、现付其他、挂账其他、现付大交通、挂账大交通、代收团费、现收现退、景区合计、酒店合计、餐厅合计、车队合计、地接成本、杂费、自费成本、财务费用、操作费、备用金、应付导游团款、导服费、报账日期。
- 团队挂账成本明细字段包括：团号、团队类型、资源类型、供应商、资源、挂账金额。

这些字段说明：订单原始金额、后续应收变更、订单总金额必须可拆；成本必须按资源类型、供应商、现付/挂账、阶段和团队统计。

## 表设计硬原则

### 订单收入侧

- `价格信息` 和 `费用变更` 是订单应收来源，不是实际收款。
- 订单原始价格和后续应收变更可以统一到一张订单收入明细表，例如 `sales_order_charge_lines`。
- 统一收入明细表必须区分：
  - `base_price`：订单原始价格。
  - `adjustment`：后续应收变更。
- 统一收入明细表必须支持金额正负号、状态、登记人、登记时间、审核/作废信息和来源类型。
- 修改订单基础价格不能覆盖历史应收变更记录。
- 作废应收变更不能物理删除，必须保留流水。

### 真实收款侧

- 真实收到客户的钱必须进入收款记录和收款分摊，不应直接写在价格明细里。
- 一笔收款可能分摊到订单团费、购物返佣、导游结算、代收团款等不同项目。
- 银行现金账必须独立保存账户流水、收入、支出、余额、经办人、登记人和销账状态。

### 成本应付侧

- 成本、应付、付款不能混入订单收入明细表。
- 成本明细必须支持资源类型、供应商、资源、费用项目、现付/挂账、成本阶段、团队、导游、计调。
- 应付项目和付款记录需要独立表，并通过付款分摊关联。
- 导游备用金、导游结算、购物返佣、应收应付冲抵、发票记录应按业务独立建模。

### 统计侧

- 财务统计和经营统计必须支持客户、供应商、团队、订单、导游、业务员、收客计调、操作计调、产品、地区、日期、审核状态、资源类型、成本阶段等维度。
- 大范围统计、首页看板、经营报表、财务汇总不能长期依赖实时扫描明细表；数据量变大后应使用汇总表、缓存、物化视图或异步快照。
- 设计明细表时必须同步考虑常用查询索引，尤其是 `tenant_id`、软删除、日期、客户、供应商、团队、订单、状态、项目类型。

## 推荐表族边界

| 表族 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 订单收入明细 | 订单原始价格、应收变更、订单应收来源。 | 实际收款、付款、成本、发票、银行账。 |
| 收款记录/分摊 | 客户实际收款、导游代收、购物返佣收款等现金收入。 | 订单价格定义。 |
| 银行现金账 | 银行/现金账户流水、转账、销账。 | 业务应收来源。 |
| 成本明细/应付项目 | 供应商、资源、导游、计调、财务阶段成本和应付。 | 客户订单收入。 |
| 付款记录/分摊 | 实际付款、预付款、企业码、导游现付等。 | 成本来源定义。 |
| 发票记录 | 客户发票和供应商票据。 | 收付款流水本身。 |
| 导游结算 | 导游收入、导游上交、备用金、现收现退、代收团款。 | 普通供应商应付。 |
| 购物返佣 | 购物消费、人头费、佣金、应收、已收、余额。 | 普通订单团费。 |
| 冲抵关系/流水 | 客户与供应商之间的应收应付冲抵。 | 原始应收、原始应付。 |

## 后续建表前检查清单

- 是否已经阅读本文件。
- 是否区分了应收来源和实际收款。
- 是否区分了成本来源、应付项目和实际付款。
- 是否保留了原始金额、后续变更、作废/审核流水。
- 是否能支持旧系统财务管理和数据统计菜单中的关键维度。
- 是否为大数据量统计预留汇总表或异步快照方案。
- 是否避免把所有金额业务塞进一张万能表。
