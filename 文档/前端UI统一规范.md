# 前端 UI 统一规范

本文档是前端页面设计和实现的执行标准。新增页面、重构页面、修弹窗、调按钮、改表格前，先按本文档判断页面类型和参考模板，再动代码。目标是让系统看起来像同一个后台产品，而不是每个页面单独设计一套风格。

## 1. 基本原则

- 优先复用现有组件和样式，不从零设计同类页面。
- 页面风格以 Vben Admin、Ant Design Vue 和当前已统一的团队安排页为基准。
- 正式业务页面要安静、清晰、密集、可扫描；不要做营销页、装饰页、展示页。
- 每个页面只服务当前业务动作，不为了视觉丰富堆卡片、色块、说明文案或大面积装饰。
- 新增自定义样式前必须先确认：现有公共组件、共享 CSS、Ant Design Vue 默认能力是否已经能满足。
- 同一类功能必须同一套交互：同样是新增、修改、查看、删除、审批、选择资源，不允许每个模块换一种按钮、弹窗和布局。

### 1.1 前端设计优化 Skill 使用规则

- 普通后台业务页优先使用 `impeccable`，重点检查信息层级、表单效率、间距、状态反馈、响应式和可访问性。
- 新页面或较大规模改版使用 `design-taste-frontend`，在符合本系统现有设计语言的前提下，避免页面模板化或过度设计。
- 需要系统化 UI/UX 方案时使用 `ui-ux-pro-max`，用于设计体系、信息架构、组件选型和跨页一致性评估。
- 只有明确的动画场景才使用 GSAP 系列 Skill；普通管理页面不随意添加动画、视差或复杂过渡。
- Skill 只作为设计检查和实现辅助，不得覆盖本文档、现有公共组件和已确定的业务交互。单个任务默认只选择一个最匹配的 Skill，不为了视觉丰富叠加多套设计风格。

## 2. 页面类型和固定模板

### 2.1 普通业务列表页

适用：客户、供应商、资源、字典、员工、合同、报价规则等常规增删改查页面。

- 页面结构固定为 `Page -> Card -> 查询区 -> 表格 -> 弹窗/抽屉`。
- 普通 CRUD 优先使用 `_business/crud/CrudPage.vue`。
- 查询区、按钮组、表格操作区优先复用 `src/components/business/` 下的公共组件。
- 查询区必须优先使用 `BusinessSearchForm.vue` 和 `BusinessActionButtons.vue`，不得再为单个列表页复制 `*-search-grid`、`*-search-actions` 这类局部样式。
- 查询区按钮顺序固定为 `重置 / 查询 / 新增`。
- `查询` 和 `新增` 使用实心主按钮；不要用 `ghost`、自定义颜色或大号按钮。
- 新增按钮文案统一为 `新增`，具体对象放在弹窗标题中，例如 `新增客户单位`、`新增供应商`。
- 表格行操作统一使用 `type="link"`、`size="small"`；删除、停用、作废等危险操作放最后，并使用 `danger`。
- 列表字段尽量一屏可扫描；确实字段多时，优先固定关键列、压缩辅助列、使用省略号和 tooltip，不要让整页出现无控制的横向滚动。

查询控件尺寸固定：

- 查询区普通输入框、下拉框、日期框统一按中等表单控件处理，高度以当前总经理审批页查询区为基准，即约 `40px`，不要一页 32px、一页 44px。
- 查询区 label 宽度默认 `96px`；短 label 可降到 `76px`，但同一页面必须统一。
- 关键词输入框推荐宽度 `260px` 到 `360px`；状态、类型等短下拉推荐宽度 `180px` 到 `240px`。
- 查询字段必须在统一网格内横向排列；不要让单个关键词框无限拉长占满整行，除非该页面只有一个查询项且有明确业务原因。
- 查询按钮高度必须和输入框视觉高度一致，按钮组右对齐。

### 2.2 团队业务工作台页

适用：团队安排、产品团队安排、团队操作、后续团队执行/审核类单团页面。

- 视觉基准固定为正式团队安排页。
- 必须复用 `src/views/sales/components/FormalTeamPageHeader.vue`。
- 必须复用 `src/views/sales/team-arrangement-layout.css` 中已有团队页头、指标、内部备注、工具条、分类入口、成本总览等样式。
- 产品团队安排页、正式团队安排页、团队操作页的顶部结构必须一致：标题区、阶段条、业务标签、指标、内部备注、右侧动作和工具按钮不能各自重画。
- 团队相关按钮区必须单行横排；按钮多时允许按钮区内部横向滚动，但不允许自动换成多行导致页面松散。
- 团队名称过长必须固定宽度、省略号和 hover/title 展示完整文本，不允许挤压导游、出发地、状态等字段。
- 团队页内部备注展示使用完整文本块，保留换行；编辑弹窗用统一内部备注弹窗。
- 同类团队属性编辑弹窗必须共用口径：普通属性 `460px`，内部备注 `760px`。

### 2.3 复杂业务录入弹窗

适用：团队安排大交通、住宿、用车、景区、用餐、自费、购物、地接、附加、导游安排、备用金申请等。

- 优先复用已有业务弹窗组件，不允许同一业务族另写一套弹窗视觉。
- 团队安排分类录入优先复用 `ArrangementEditorModal.vue` 和 `arrangement-editor-model.ts`。
- 弹窗结构优先使用 Ant Design Vue 标准 `Modal + Form + Select/Input/InputNumber/Textarea/Table/List`。
- 弹窗底部按钮使用默认操作区或统一的右对齐 footer，按钮顺序为 `取消 / 保存` 或 `取消 / 确认`。
- 普通小弹窗宽度 `460px`；内部备注、复杂说明类弹窗宽度 `760px`；大表选择和拼团/转团类弹窗可用 `960px` 或 `1120px`，但必须有明确业务原因。
- 表单字段按业务录入顺序分组，不要用卡片套卡片；除非已有公共组件，否则不要在弹窗里堆多层自定义面板。
- 弹窗内数字、金额、比例字段使用 `InputNumber`，并通过 `addon-before/addon-after` 标识单位，例如 `¥`、`%`、`人`、`天`。
- 弹窗内下拉数据必须按业务懒加载，只加载当前弹窗需要的数据，不一次性拉无关供应商、员工、资源和字典。

### 2.4 财务、统计、审批页

适用：应收、应付、收付款、银行现金账、导游备用金、财务审核、数据统计、经营报表。

- 页面优先使用密集表格、清晰筛选和可对账字段，不做装饰性卡片堆叠。
- 金额字段必须右对齐，统一金额格式，重要汇总可以做摘要条，但不能替代明细表。
- 审批页展示重点是申请来源、金额明细、异常提示、审批记录和操作按钮，不要做复杂视觉包装。
- 财务和统计页面的正式金额必须来自后端接口或后端校验结果，前端本地计算只能做未保存表单预览。
- 查询条件涉及日期、客户、供应商、团队、状态时，控件顺序应和业务查账习惯一致：日期范围优先，其次对象、状态、关键字。

## 3. 统一视觉规则

- 主色使用系统默认蓝色和 Ant Design Vue 默认状态色，不为单页发明新主色。
- 页面背景、卡片、表格、弹窗保持白、浅灰、浅蓝灰为主；禁止大面积渐变、强装饰色块、复杂阴影。
- 卡片圆角控制在 `6px` 到 `8px`；不要为了视觉效果使用大圆角卡片。
- 页面标题、卡片标题、表格文字、表单标签字号必须和现有页面接近；不要在业务后台里使用过大的展示型标题。
- 字段值过长必须使用省略号、换行或 tooltip；不允许文本挤压相邻字段、越界、遮挡按钮。
- 不使用页面内说明文字介绍“如何使用这个功能”，除非业务本身必须提示风险或规则。
- 图标优先使用 `lucide` 或系统已用图标，不手写零散 SVG。
- 相同层级的按钮、标签、状态、统计卡片必须视觉一致；不要一页内混用多种按钮形态表达同一动作。

## 4. 弹窗和抽屉规则

- 新增、修改、查看详情优先用 Modal；超长表单、地图、行程编辑、大量步骤才用 Drawer 或独立页面。
- 小表单弹窗宽度默认 `460px`。
- 长文本、内部备注、说明编辑弹窗默认 `760px`，文本框最少 8 到 10 行，保留换行。
- 大表选择弹窗宽度按业务使用 `960px` 或 `1120px`，表格必须设置合理 `scroll`，不能撑破弹窗。
- 弹窗标题必须直说业务动作，例如 `修改业务类型`、`内部备注`、`选择导游`。
- 弹窗内不使用夸张卡片、渐变背景、营销式标题和独立配色。
- 关闭弹窗时要清理编辑态，避免从“修改”切到“新增”时误带上一条数据。

## 5. 表格和列表规则

- 列表必须分页，前端不能无条件加载全表。
- 表格列宽要主动设计，关键列固定或给足宽度，辅助列压缩。
- 普通列表表格密度统一使用 Ant Design Vue `size="small"` 或与公共列表页等效的紧凑行高；不要同类列表一页宽松、一页紧凑。
- 表头高度、单元格上下 padding 和字体大小必须接近当前总经理审批页、团队管理页等已统一列表。
- 表格外层 Card 内边距保持统一，不要一页留大空白、一页贴边。
- 长文本列使用省略号和 tooltip；备注类可以多行截断，但不能把行高撑到不可扫描。
- 金额列右对齐；数量、状态、日期等列居中或按现有同类页面处理。
- 状态用 `Tag` 或统一状态样式，不要每个页面自定义不同颜色体系。
- 行内操作不要使用实心按钮；列表行操作统一 link 风格。

## 6. 按钮和操作区规则

- 查询区固定 `重置 / 查询 / 新增`。
- 弹窗 footer 固定 `取消 / 保存` 或 `取消 / 确认`，主动作在右侧。
- 顶部工具条按钮使用图标加文字，保持单行、等高、统一间距。
- 危险动作必须明确放在操作组最后，并使用危险色。
- 不允许把同级按钮一部分放顶部、一部分放底部，除非业务区分“页面工具”和“表格行操作”。
- 不允许为了放下按钮随意缩小字体到不可读，也不允许让按钮自动挤成参差不齐的两行。

## 7. 新增页面前的检查清单

开发前必须确认：

- 这个页面属于哪种页面类型：普通列表、团队工作台、复杂弹窗、财务统计、审批。
- 同类页面当前最接近的参考页面是哪一个。
- 是否已有公共组件、共享 CSS 或业务弹窗可以复用。
- 是否需要老系统调研；普通样式问题不需要，业务逻辑对齐需要。
- 是否涉及金额、状态、审批、财务或数据库；涉及时必须按后端权威计算和对应测试规则处理。

开发后必须确认：

- 页面能打开，没有明显错位、越界、遮挡、文字挤压。
- 弹窗宽度、按钮顺序、表格操作和同类页面一致。
- 长文本有省略号、tooltip 或合理换行。
- 涉及前端代码时至少跑相关前端测试或 `pnpm -F @vben/web-antd run typecheck`。
- 涉及视觉统一时，用浏览器实际打开页面检查，不只看代码。

## 8. 禁止事项

- 禁止同一类页面重新设计一套按钮、弹窗、卡片和标题风格。
- 禁止卡片套卡片、页面大面积装饰块、渐变背景、强阴影、花哨状态条。
- 禁止把后台业务页面做成营销落地页、展示页或说明页。
- 禁止在弹窗中一次性加载无关下拉数据。
- 禁止在页面里散写请求地址、散写查询区样式、散写表格操作区样式。
- 禁止因为当前功能简单就跳过同类页面对齐。
- 禁止只凭截图感觉改样式，改完必须至少做页面级检查。

## 9. 当前明确基准

- 普通 CRUD 基准：已迁移到 `components/business` 和 `_business/crud/CrudPage.vue` 的客户、采购、企业资料类列表页。
- 团队工作台基准：`sales/team/arrangement.vue`。
- 产品团队安排和团队操作必须继续与团队工作台基准保持一致。
- 团队页头基准组件：`sales/components/FormalTeamPageHeader.vue`。
- 团队页共享样式：`sales/team-arrangement-layout.css`。
- 团队安排分类弹窗基准：`sales/components/ArrangementEditorModal.vue`。
