# 老系统调研：销售团期管理按钮级验证

调研日期：2026-06-22  
调研页面：`销售管理 / 产品管理 / 团期管理`  
样本产品：`GroupId=270648`  
页面地址：`http://www.mtravel.cn/sale/LineGroupList.aspx?menu=A5&GroupId=270648`

本文用于新系统开发前确认老系统真实行为。结论优先服务后续建表、接口拆分和页面复刻。

## 1. 页面定位

团期管理挂在产品下面，不是一个脱离产品的独立新增页。

入口链路：

- `销售管理 / 产品管理`
- 进入某个产品详情
- 顶部页签切换到 `团期管理`

老系统创建团期后，会直接生成可进入 `团队操作` 的团队记录。样本团期点击团号后进入：

`/sale/TeamOperation.aspx?GroupId=团队ID`

团队详情中显示团队类型为 `散拼`。因此新系统按老系统开发时，产品下的团期管理默认生成 `散拼` 团队。

## 2. 团期列表字段

列表字段如下：

- 全选
- 团号
- 发团日期
- 操作计调
- 状态
- 总位 / 余位
- 单房差价格
- 客户类型
- 成人
- 儿童
- 儿童不占床
- 老人
- 附加费用
- 操作

注意：老系统一条团队可以有多条客户类型价格。页面结构上，团队主信息用 `rowspan` 跨多行，第二行开始只显示客户类型和价格。

例如测试团 `CS-SP-BK-261015G`：

- 默认价格行：`GroupPriceId=76480`
- A类客户价格行：`GroupPriceId=77154`

新系统不能按“一行表格 = 一个团队”理解，应该按 `团队主表 + 团队价格明细表` 设计。

## 3. 批量添加团队

按钮：`批量添加团队`  
弹窗地址：`/sale/pop/LineGroupBatchPrice.aspx?GroupId=270648`

弹窗有两个页签。

### 3.1 批量团期

用途：按连续日期范围和星期批量生成团期。

主要字段：

- 开始日期：`date1`
- 结束日期：`date2`
- 客户分类：`BuyerTypeId`
- 操作计调：`OperatorId`
- 预控人数：`AllNum01`
- 单房差：`RoomPrice01`
- 附加费用：`Price05`
- 成人价格：`Price01`
- 儿童价格：`Price02`
- 儿童不占床价格：`Price03`
- 老人价格：`Price04`
- 星期：`weekday`
- 提交按钮：`btnSubmit1`

验证结论：

- 创建后直接在团期列表生成团队。
- 重复日期不会被老系统阻止，会继续生成新的团号后缀。
- 团号后缀从 `A/B/C...` 增长，重复很多后会出现 `Z0/Z1...`。

### 3.2 特定团期

用途：从日期列表中挑选若干指定日期生成团期。

主要字段：

- 可选日期：`OptionalDate`
- 已选日期：`SelectedDate`
- 客户分类：`BuyerTypeId2`
- 操作计调：`OperatorId2`
- 预控人数：`AllNum02`
- 单房差：`RoomPrice02`
- 附加费用：`Price05_2`
- 成人价格：`Price01_2`
- 儿童价格：`Price02_2`
- 儿童不占床价格：`Price03_2`
- 老人价格：`Price04_2`
- 提交按钮：`btnSubmit2`

验证结论：

- 特定团期页签在页面里初始是隐藏区域，自动化测试必须先切换页签或用页面函数移动日期。
- 生成逻辑和批量团期一致，都会生成团队记录。

## 4. 行内编辑

老系统列表中的总位、单房差和价格可以直接改。输入框失焦后弹确认：

`确认要修改该内容吗?`

接口行为：

- 修改总位：`Action=EditGroup&GroupId=271403&Field=AllNum&Val=90`
- 修改单房差：`Action=EditGroup&GroupId=271403&Field=RoomPrice&Val=810`
- 修改成人价：`Action=EditGroupPrice&GroupId=271403&GroupPriceId=76468&Field=Price01&Val=1810`
- 修改儿童价：`Action=EditGroupPrice&GroupId=271403&GroupPriceId=76468&Field=Price02&Val=1310`

结论：

- `AllNum`、`RoomPrice` 属于团队主信息。
- `Price01` 到 `Price05` 属于团队价格明细。
- 新系统接口要按字段或小粒度动作拆分，不能每次保存重建整个产品或全部团期。

## 5. 删除价格

列表行内 `删除` 是删除某条客户类型价格，不是删除团队。

老系统行为：

- 点击价格行的 `删除`
- 弹确认：`确定要删除该条记录吗？`
- 请求：`Action=delGroupPrice&GroupPriceId=76460`
- 删除后团队仍保留，价格行变为空或减少一条

结论：

- 新系统必须把 `删除价格` 和 `删除团队` 分开。
- 价格明细删除应只影响 `sales_team_prices` 这一类明细，不应删除团队主记录。

### 6.3 团队停售

按钮：`btnStop`

### 6.4 团队恢复收客

按钮：`btnStart`  
确认提示：`确认要恢复收客选中的团期吗?`

验证结果：

- 状态从 `停售` 变为 `正常`。

### 6.5 删除团队

按钮：`btnDel`  
确认提示：`只有被取消的团队可以删除,确认要删除选中的团期吗?`

验证结果：

- 对 `取消` 状态团队执行删除后，列表中查不到该团。
- 对 `正常` 状态团队执行删除后，老系统提示：`除团期：2026-10-15不是取消状态无法删除以外,其余团期已删除!`
- 正常状态团队不会被删除，记录仍在。

结论：

- 新系统删除团队前必须校验状态。
- 只有取消状态可以进入删除流程。
- 新系统仍建议做软删除，不做物理删除。

### 6.6 同步产品内容

作用判断：

- 用于把产品模板内容同步到选中团期对应的团队。
- 具体覆盖哪些字段，老系统页面没有明示，需要后续甲方确认。

### 6.7 同步产品内容（不含单房差）

按钮：`btnSynchronize2`  
确认提示：`确认要同步产品内容到选中的团期吗?`  
成功提示：`同步成功!`

提交字段：

- `btnSynchronize2=同步产品内容(不含单房差)`

结论：

- 这是同步产品内容的变体，区别是不覆盖单房差。
- 新系统应明确做成两个动作：`同步产品内容`、`同步产品内容但保留团期单房差`。

## 7. 添加/修改团期信息

按钮：`添加/修改团期信息`  
弹窗地址：`/sale/pop/LineGroupPriceAdd.aspx?GroupIdList=团队ID列表&LineId=产品ID`

弹窗用途：对已有团期批量改信息，不是新增日期。

主要区域：

- 可选团期
- 已选团期
- 可选客户分类
- 已选客户分类
- 同步产品内容
- 同步产品内容（不含单房差）
- 删除价格
- 修改预控人数
- 修改单房差
- 修改价格

可操作字段：

- 预控人数：`AllNum`
- 单房差：`RoomPrice`
- 成人价格：`Price01`
- 儿童价格：`Price02`
- 儿童不占床价格：`Price03`
- 老人价格：`Price04`
- 附加费用：`Price05`

规则：

- 必须选择团期。
- 客户分类可以不选。
- 不选客户分类时，老系统提示含义是：修改原有所有价格；如果原先无价格，则添加为默认价格。
- 选中客户分类后，可为该客户分类新增或修改价格行。
- 勾选 `删除价格` 时，用于删除选中客户分类价格。

已验证行为：

- 使用页面自带 `moveToRight('OptionalBuyerType','SelectedBuyerType')` 选择 `A类客户` 后，能新增 A类客户价格行。
- 直接用脚本插入右侧下拉选项不等同于页面真实操作，老系统后端不一定识别。

老系统缺陷：

- 弹窗里的 `同步产品内容（不含单房差）` 单独勾选时，前端校验仍提示 `请选择需要的功能!`。
- 原因是老系统 JS 校验只判断了 `chkSynchronize`，没有把 `chkSynchronize2` 纳入功能选择判断。
- 新系统不要复刻这个缺陷。

## 9. 新系统实现要求

### 9.1 数据表建议

团期管理不建议单独做一套孤立主表。建议沿用统一团队主链路：

- `sales_teams`：团队主表，保存团号、产品、团队类型、日期、天数、状态、操作计调、预控人数、余位等。
- `sales_team_prices`：团队价格明细，按团队和客户分类保存成人、儿童、儿童不占床、老人、附加费用。
- `sales_team_status_logs`：团队状态变化日志。
- `sales_team_no_logs`：团号生成和变更日志。

如果后续需要保留“产品计划团期”和“正式团队”两阶段，可以再补计划表；但按老系统现状，创建团期就是创建可收客团队。

### 9.2 接口拆分要求

必须拆成小粒度接口：

- 查询产品下团期列表
- 批量生成连续日期团期
- 按指定日期生成团期
- 修改团队预控人数
- 修改团队单房差
- 修改某条客户分类价格
- 新增客户分类价格
- 删除客户分类价格
- 批量取消团队
- 批量恢复取消
- 批量停售
- 批量恢复收客
- 删除已取消团队
- 同步产品内容
- 同步产品内容但保留单房差

不要做一个“大保存接口”一次性重建全部团期和价格。

### 9.3 状态规则

团期状态至少需要：

- `NORMAL`：正常
- `STOPPED`：停售
- `CANCELLED`：取消
- `DEPARTED`：发团
- `FINISHED`：完成，后续团队主链路使用

删除规则：

- 只有 `CANCELLED` 状态允许删除。
- 删除建议使用软删除。
- 已有关联订单、计调安排、财务记录时，删除限制需要单独校验。

### 9.4 页面复刻要求

新系统第一版需要保留老系统核心操作：

- 产品详情页保留 `团期管理` 页签。
- 列表保留老系统字段和底部批量按钮。
- 支持多客户分类价格行。
- 支持直接修改总位、单房差和价格。
- 支持 `添加/修改团期信息` 批量调整。
- 团号点击进入团队操作页。

页面可以优化样式，但按钮含义、字段和业务链路不能缩水。

## 10. 待甲方确认

- 团号前缀如 `CS-SP-BK`、`CS-SP-CS` 的精确含义和生成规则。
- 重复日期是否允许无限生成多个团期，还是新系统需要提醒重复。
- 产品内容同步到团期时，具体覆盖哪些字段：行程、产品说明、收客须知、内部备注、团队安排、价格等。
- `同步产品内容（不含单房差）` 是否只保留单房差，价格和其他内容是否仍覆盖。
- 已有订单后，团期价格修改是否影响已确认订单应收，还是只影响新订单。
- 已收客、已排团、已发团、已结算的团队，分别允许修改哪些字段。
- 删除已取消团队时，如果已有订单、游客、计调安排、财务记录，是否允许删除。
