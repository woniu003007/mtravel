# 客户单位字段老系统调研结果

调研页面：老系统 `客户单位管理 / BuyerManage.aspx`

## 调研结果

### 业务代码

老系统里是客户单位的短编码。

新增客户时是必填项，页面提示：可用大写字母和数字，最多 6 位字符。

列表和搜索条件里都有 `业务代码`，说明它主要用于快速识别和查询客户单位。

### 操作计调

老系统里是分配给客户单位的内部计调人员。

列表中可能显示具体员工名，也可能显示 `未分配`。

它不是客户方联系人，应该理解为公司内部后续负责该客户团队安排或计调对接的人。

### 负责人

老系统里是客户单位那边的联系人或负责人。

新增客户时是必填项，和联系电话一起属于客户单位基础联系信息。

它不是内部操作人员，也不是登记人。

## 简单结论

- `业务代码`：客户单位快速识别码。
- `操作计调`：公司内部负责该客户的计调人员。
- `负责人`：客户单位那边的联系人。

## 操作计调后续用途

### 0. 操作计调人员从哪里录入

截图里的操作计调人员来自老系统 `企业资料 / 员工管理`。

老系统入口：`企业资料 -> 员工管理`

员工管理列表字段包括：业务代码、员工名称、用户名、部门、角色、查看范围、性别、电话、手机、创建时间、状态、操作。

新增员工入口是 `添加/修改员工信息`，主要字段包括：

- 业务代码
- 姓名
- 用户名
- 性别
- 手机号
- 电话
- 部门
- 角色
- 信息查看范围
- 利润查看范围
- 收客查看范围
- 客户查看范围

截图下拉里的人员在员工管理中可以匹配到，例如：

- 黄建国：员工管理中存在，角色为管理员。
- 陈爱晚：员工管理中存在，部门为计调部。
- 林楷：员工管理中存在，部门为计调部，角色为计调经理。
- 老板号：员工管理中存在，角色为总经理。
- 南京员工：员工管理中存在，部门为南京分公司，角色为计调【南京】。
- 演示：员工管理中存在，角色为总经理。
- gejing：员工管理中存在，部门为组团业务部，角色为组团计调。

所以新系统里，`操作计调` 不需要单独建一套“计调人员表”，应该从系统用户/员工表中选择。

### 1. 客户单位上的默认计调

客户单位里可以先设置 `操作计调`。

它表示这个客户后续由哪个内部计调人员对接，不是客户联系人。

### 2. 团队上的实际操作计调

团队生成后，团队详情和团队安排总览里会显示 `操作计调`。

示例：团队主信息中显示 `操作计调：老板号[Tel：13898989898]`。

团队页面上的 `操作计调` 可以点击修改，老系统会打开 `修改操作计调` 弹窗。

### 3. 后续页面按操作计调筛选团队

老系统多个后续页面都有 `操作计调` 查询条件：

- 销售管理 / 团队管理
- 计调操作 / 团队安排
- 计调操作 / 团队审核
- 财务管理 / 团队审核

这些页面用它来筛选某个计调负责的团队。

### 4. 统计按操作计调归集

老系统统计里也使用 `操作计调`：

- 团队进度统计：按操作计调统计团队安排、导游报账、计调审核、财务审核完成情况。
- 收客统计：有 `按操作计调` 统计口径。
- 利润统计：有 `按操作计调` 统计口径。

### 5. 系统配置会影响默认筛选

老系统参数里有 `搜索操作计调默认显示自己`。

这说明普通计调进入相关页面时，系统可以默认只看自己负责的团队。

## 对新系统的理解

`操作计调` 应该设计成“团队履约责任人”。

客户单位上的 `操作计调` 是客户责任归属；团队上的 `操作计调` 是实际负责人。

后续团队安排、计调审核、财务审核和统计分析，都应该能按这个字段筛选或汇总。

本次没有在老系统执行新增团队保存，所以“客户单位的操作计调是否一定自动带到新团队”还不能写死，需要后续再确认。
