# 老系统调研：销售管理 / 产品管理

更新时间：2026-06-12

## 1. 调研范围

本次只读调研老系统 `销售管理 / 产品管理`，用于后续开发新系统产品管理模块。

证据等级：`A`，已通过旧系统实页确认。

## 2. 旧系统入口

| 页面 | 旧系统地址 | 作用 |
| --- | --- | --- |
| 产品管理列表 | `/sale/LineManage.aspx` | 查看线路/产品模板列表。 |
| 添加/修改产品-基本信息 | `/sale/LineAdd.aspx` | 维护产品基础资料。 |
| 添加/修改产品-行程内容 | `/sale/LineAdd02.aspx` | 按天维护行程、住宿、用餐和关联酒店。 |
| 添加/修改产品-产品说明 | `/sale/LineAdd03.aspx` | 维护收客须知、费用包含、不含、儿童安排等说明。 |
| 业务类型管理 | `/sale/BusinessTypeManage.aspx` | 维护产品下可用业务类型。 |
| 团期管理 | `/sale/LineGroupList.aspx` | 从产品生成团期/团队，维护发团日期、余位、价格和销售状态。 |

## 3. 产品列表页事实

列表字段：

- 序号
- 出发地
- 产品名称
- 标准
- 天数
- 创建人
- 创建时间
- 操作

顶部动作：

- 附加费管理
- 添加产品
- 搜索

行内操作：

- 创建团队
- 团期管理
- 修改产品
- 删除产品
- 团队安排
- 返点规则
- 产品授权

关键判断：

- 老系统的“产品”不是普通商品资料，而是线路模板。
- 产品可以下钻到团期、团队安排、返点规则和客户授权。
- 删除产品是高风险动作，老系统有确认提示。

## 4. 产品基本信息页事实

基本信息页标题为 `添加/修改产品`，顶部有以下标签页：

- 基本信息
- 行程内容
- 产品说明
- 团队安排
- 业务类型管理
- 团期管理

主要字段：

- 业务类型
- 国内 / 国际
- 线路名称
- 接团城市：省 / 市 / 区县
- 出团日期
- 出团类型：每天发 / 每周发 / 不定期
- 接待标准
- 产品主题
- 旅游天数
- 截止收客：出团前多少天截止
- 单人房差
- 预控人数

按钮：

- 保存产品基本信息
- 返回

关键判断：

- 产品基础资料里已经包含住宿标准、出团规则、收客截止和预控人数。
- 新系统开发时不能只做“产品名称、天数、价格”的轻表。

## 5. 行程内容页事实

行程内容按天维护。

每一天包含：

- 行程标题
- 行程内容
- 住宿说明
- 关联酒店
- 旺季附加费
- 早餐 / 中餐 / 晚餐
- 路书地点

页面动作：

- 导入行程
- 添加地点
- 保存
- 返回

关键判断：

- 产品行程是模板化的每日行程。
- 行程中可以关联酒店资源。
- 用餐安排在产品模板阶段已经有早餐、中餐、晚餐勾选。
- 路书是后续可扩展能力，第一版可以先记录地点/行程文本，不一定先做地图。

## 6. 产品说明页事实

产品说明页维护销售和合同/行程单可复用的说明文本。

字段包括：

- 收客须知
- 产品说明
- 费用包含
- 费用不含
- 儿童安排
- 购物安排
- 自费项目
- 赠送项目
- 注意事项
- 温馨提醒

关键判断：

- 这些说明不是备注字段，应作为产品模板的一部分。
- 后续报价单、行程单、电子合同或确认件可能会复用这些内容。

## 7. 业务类型管理事实

业务类型管理是产品内部的类型维护页面。

列表字段：

- 序号
- 类型名称
- 创建人
- 创建时间
- 操作

旧系统示例类型：

- 疗休养
- 定制团
- 红色培训
- 门票冲量
- 特惠游
- 漂流
- 落地散
- 地接团
- 周边游
- 办公费用
- 杂项经费

关键判断：

- 业务类型既可以全局维护，也可以作为产品选择项使用。
- 新系统第一版可以先做成产品基础信息里的可选字典，后续再扩展为独立管理。

## 8. 团期管理事实

团期管理是产品到团队之间的关键层。

列表字段：

- 全选
- 团号
- 发团日期
- 操作计调
- 状态
- 总位 / 余位
- 单房差价格
- 客户类型
- 成人
- 儿童
- 儿童不占床
- 老人
- 附加费用
- 操作

页面动作：

- 批量添加团队
- 搜索
- 取消团队
- 恢复取消团队
- 团队停售
- 团队恢复收客
- 删除团队
- 同步产品内容
- 同步产品内容不含单房差
- 添加 / 修改团期信息

关键判断：

- 产品不是直接等于团队。
- 产品下面必须有团期层。
- 团期承载发团日期、库存余位、客户类型价格、单房差、附加费用和销售状态。
- 团期后续才进入团队收客、订单、计调安排。

## 9. 新系统开发口径

建议新系统销售产品管理拆成两层开发：

### 第一层：产品模板

负责维护线路产品本身：

- 产品名称
- 业务类型
- 国内 / 国际
- 接团城市
- 出团类型
- 接待标准
- 产品主题
- 旅游天数
- 截止收客天数
- 单人房差
- 预控人数
- 行程内容
- 产品说明
- 费用包含 / 不含
- 儿童安排
- 购物 / 自费 / 赠送 / 注意事项 / 温馨提醒

### 第二层：团期计划

负责产品的可销售日期和价格库存：

- 发团日期
- 团号
- 操作计调
- 状态
- 总位
- 余位
- 单房差价格
- 客户类型价格
- 成人价
- 儿童价
- 儿童不占床价
- 老人价
- 附加费用
- 停售 / 恢复收客
- 同步产品内容

## 10. 暂不建议第一版做重的能力

以下能力可以先留接口和字段，不建议第一版过度复杂：

- 路书地图计算。
- 返点规则完整闭环。
- 产品授权和客户授权联动。
- 产品内容同步到已收客团队时的差异比对。
- AI 自动生成行程。

第一版重点应先跑通：

```text
产品模板 -> 团期 -> 团队 -> 订单
```

## 11. 产品相关字典配置结论

本节补充调研旧系统中哪些产品基础项有配置入口，哪些只是页面固定选项。

| 项目 | 旧系统实页表现 | 是否有明确配置入口 | 新系统建议 |
| --- | --- | --- | --- |
| 业务类型 | 产品基本信息中下拉选择；产品详情顶部有 `业务类型管理` 标签页，页面支持 `添加`、列表和操作。 | 有 | 做成可配置字典。 |
| 国内 / 国际 | 产品基本信息中固定下拉，只有 `国内`、`国际`。 | 未发现 | 做成代码枚举。 |
| 出团类型 | 产品基本信息中固定下拉，只有 `每天发`、`每周发`、`不定期`。 | 未发现 | 做成代码枚举。 |
| 接待标准 | 产品基本信息中单选项，包含商务/快捷、携程两钻、准三星、挂牌三星、携程三钻、挂牌四星、准四星、携程四钻、携程五钻等。 | 未在菜单或系统参数中发现维护入口 | 新系统建议做成可配置字典，默认初始化老系统选项。 |
| 产品主题 | 产品基本信息中单选项，包含观光、美食、夕阳红、亲子游、摄影、滑雪、夏令营、春节、五一、中秋、国庆、元旦等。 | 未在菜单或系统参数中发现维护入口 | 新系统建议做成可配置字典，默认初始化老系统选项。 |
| 团期状态 | 团期管理通过按钮形成状态变化，例如团队停售、团队恢复收客、取消团队、恢复取消团队。 | 不是字典配置，是业务状态流转 | 做成代码枚举和状态流转。 |
| 费用项目 / 附加费用 | 企业资料下有 `费用项目` 页面，支持添加，按景区、酒店、餐厅、车队、大交通、其它、杂费、地接、附加费用、购物分类维护。 | 有 | 复用已开发费用项目模块，团期附加费用引用该模块。 |
| 资源类目 | 存在 `资源类目管理` 页面，当前看到酒店、景区类目，例如五星级酒店、四星级酒店。 | 有，但偏采购/资源分类，不是产品接待标准 | 不作为产品接待标准直接使用。 |

旧系统 `系统参数配置` 页面中未发现产品业务类型、接待标准、产品主题、出团类型、团期状态的配置项；该页面主要是登录限制、计调审核、导游报账、财务限制、订单字段显示、预控人数校验等系统规则。

因此新系统开发建议：

- `业务类型`：按老系统做可配置。
- `费用项目 / 附加费用`：复用企业资料费用项目。
- `国内 / 国际`、`出团类型`、`团期状态`：按固定枚举。
- `接待标准`、`产品主题`：老系统没有明显配置入口，但新系统建议做成系统字典，便于甲方后续维护。
