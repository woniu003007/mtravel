# MTravel 系统使用说明书（业务版）

> 说明：本说明书基于 2026-05-09 对 `http://www.mtravel.cn` 的只读调研整理，用于帮助管理层和业务人员理解系统用途、标准使用顺序和各模块职责。本文不是厂商官方操作手册，不包含任何写入示范。

## 一、系统是什么

MTravel 是一套面向旅行社/地接社的经营管理系统。  
它把以下业务放在同一条链路中：

- 客户管理
- 采购资源管理
- 产品与团期管理
- 团队与订单管理
- 游客与电子合同管理
- 计调资源安排
- 财务审核与收支结算
- 经营统计与报表

这套系统最核心的业务对象不是单个客户，也不是单张订单，而是`团队`。  
团队把销售、计调、财务和统计都串起来。

## 二、系统能解决什么问题

### 1. 解决客户、订单、团队数据分散

把客户、产品、订单、游客、合同、导游、供应商、收付款放在一套系统里统一管理。

### 2. 解决销售、计调、财务之间接力混乱

销售建团和下单后，计调直接在团队上排资源，财务直接在团队上做审核和结算，不需要反复人工抄录。

### 3. 解决团队履约过程难跟踪

每个团队的导游、交通、住宿、用车、景区、用餐、自费、购物、地接都能按团队统一查看。

### 4. 解决财务对账困难

系统能统一查看：

- 应收、已收、余款
- 应付、已付、余款
- 导游备用金、导游结算
- 购物返佣
- 发票
- 银行现金账

### 5. 解决管理层看不到经营结果

系统可输出：

- 收客统计
- 利润统计
- 团队进度统计
- 账款统计
- 导游统计
- 报表中心汇总报表

- 回款是否到账

## 四、第一次使用前要准备什么

正式跑业务前，建议先完成以下基础资料。

### 1. 企业资料

需要先建立：

- 部门
- 角色
- 员工
- 导游
- 银行账号
- 费用项目
- 接送站
- 合同模板

### 2. 系统设置

需要确认：

- 是否限制同一用户同时登录
- 财务审核后是否锁定修改
- 财务费用是否计入利润
- 团号是否默认锁定
- 是否显示散拼团队预订
- 订单管理显示哪些字段

### 3. 客户和供应商主数据

需要准备：

- 客户单位
- 客户分类
- 客户合同
- 资源主档
- 供应商档案
- 采购关系
- 采购合同

### 4. 产品和团期

要先建：

- 产品
- 团期
- 对应的团队

没有前面的主数据，后面的订单、团队安排、财务结算会不完整。

## 五、系统正确使用顺序

不要按菜单随意点，建议按下面顺序使用：

1. `企业资料`、`系统设置`  
先配组织、员工、导游、银行账号、费用项目和参数规则。

2. `客户管理`、`采购管理`  
把客户、供应商、资源、合同准备好。

3. `销售管理`  
先建产品，再建团期，再生成团队，再录订单和游客。

4. `计调操作`  
围绕团队做导游、交通、住宿、用车、景区、用餐、自费、购物、地接安排。

5. `审核`  
先计调审核，再财务审核。

6. `财务管理`  
做应收、应付、收款、付款、导游结算、返佣、发票、现金银行账。

7. `数据统计`  
最后看团队进度、收客、利润和管理报表。

一句话概括：

`建基础资料 -> 建产品 -> 建团 -> 下订单 -> 排团 -> 审核 -> 收付款 -> 看统计`

## 六、各模块使用说明

## 1. 首页工作台

### 作用

首页是工作台，不是业务录入主入口。主要用于查看概况和进入常用菜单。

### 主要用途

- 看资源概览
- 看合同提醒
- 看收客统计
- 进入快捷菜单

### 使用建议

- 老板每天先看首页，再看统计和财务
- 业务人员把常用模块放入快捷菜单

## 2. 客户管理

### 作用

管理客户主档、客户分类和客户合同。

### 主要页面

- 客户单位
- 客户分类
- 合同管理（客户）

### 标准使用方法

1. 先建立客户分类
2. 再建立客户单位
3. 补充客户合同
4. 如有需要，做产品授权
5. 后续从客户维度查看应收

### 适用场景

- 新增合作客户
- 管理客户业务归属
- 查看客户合同有效期
- 对客户应收做跟踪

### 输出结果

- 客户可以在订单中被选择
- 客户对应的应收账款可以被汇总

## 3. 采购管理

### 作用

管理资源、供应商、采购关系、采购合同和车辆。

### 主要页面

- 资源总览
- 供应商管理
- 采购关系管理
- 合同管理（采购）
- 车辆管理

### 标准使用方法

1. 先建资源
2. 再建供应商
3. 再做资源与供应商关系绑定
4. 补采购合同
5. 维护车辆档案

### 适用场景

- 建酒店、景区、餐厅、车队、购物店、地接社资源
- 建供应商结算关系
- 为计调排团提供可选资源

### 输出结果

- 团队安排时能选择资源和供应商
- 财务应付和付款可以找到对应对象

## 4. 销售管理

### 作用

这是系统的前台业务入口，负责把“可卖的产品”变成“真实订单”。

### 主要页面

- 产品管理
- 团队管理
- 订单管理
- 散拼团队预订
- 拼团订单
- 订单费用变更
- 电子合同
- 历史团队
- 团号日志
- 名单查重
- 客人信息

### 标准使用方法

1. 在产品管理里建立线路/产品模板
2. 在团期管理里建立出发批次
3. 由团期生成团队
4. 在订单管理中录客户订单
5. 补游客信息和名单
6. 如有需要，生成电子合同
7. 对费用变更做记录

### 核心理解

- `产品`是模板
- `团期`是时间批次
- `团队`是业务主对象
- `订单`是实际销售单据

### 适用场景

- 散拼团
- 整团/定制团
- 单项业务
- 拼团业务

### 输出结果

- 团队中挂上订单
- 订单中挂上游客、价格、酒店、接送等信息
- 后续可交由计调排团

## 5. 计调操作

### 作用

把销售订单变成真实履约安排。

### 主要页面

- 团队安排
- 团队审核
- 导游排班汇总
- 接送信息
- 房态控制
- 应用中心

### 标准使用方法

1. 从团队进入团队安排
2. 分别补导游、交通、住宿、用车、景区、用餐、其他、自费、购物、地接
3. 查看接送信息
4. 必要时查看房态和导游排班
5. 进入团队审核

### 核心理解

计调不是改一个表单，而是按资源类型逐页安排。

### 输出结果

- 团队履约资源齐备
- 团队成本形成
- 可进入计调审核和财务审核

## 6. 财务管理

### 作用

把团队收入、成本、收付款、发票、导游结算统一闭环。

### 主要页面

- 团队审核（财务）
- 团队预付款
- 银行现金账
- 应收帐款
- 应收账款明细
- 应付帐款
- 应付账款明细
- 成本明细预览
- 导游备用金
- 导游结算
- 购物返佣
- 收款记录
- 付款记录
- 发票记录
- 付款发票明细
- 财务收支进度
- 应收应付冲抵

### 标准使用方法

1. 先看团队财务审核
2. 从团队维度核对应收、应付和利润
3. 对客户做收款记录
4. 对供应商做付款记录
5. 处理导游备用金和导游结算
6. 处理返佣、发票、票据
7. 最后在银行现金账核对流水

### 核心理解

财务不是单独记账，而是跟着团队业务单据走。

### 输出结果

- 团队收入、成本、利润清楚
- 客户和供应商账款清楚
- 现金和银行流水清楚

## 7. 数据统计

### 作用

将业务结果转成管理分析。

### 主要页面

- 团队进度统计
- 收客统计
- 利润统计
- 资源采购统计
- 账款统计
- 导游统计
- 收款汇总统计
- 付款汇总统计
- 报表中心

### 标准使用方法

1. 先看团队进度
2. 再看收客和利润
3. 再看资源采购和账款
4. 最后按报表中心导出正式报表

### 输出结果

- 知道哪些团没安排完
- 知道哪些团利润异常
- 知道哪些客户没回款、哪些供应商待付款

## 8. 企业资料

### 作用

维护组织、账号、导游、费用项目、模板等基础主数据。

### 主要页面

- 银行帐号
- 部门管理
- 角色管理
- 员工管理
- 导游管理
- 费用项目
- 接送站管理
- 公众号管理
- 合同模板管理

### 使用建议

- 组织类数据尽量集中维护
- 员工、角色、导游不要随意混改
- 费用项目和合同模板最好固定管理人

## 9. 系统设置

### 作用

控制系统规则、展示方式和日志审计。

### 主要页面

- 页眉页脚印章
- 系统风格设置
- 快捷菜单设置
- 系统参数配置
- 电子合同配置
- 系统操作日志

### 重点理解

其中最重要的是：

- `系统参数配置`
- `电子合同配置`
- `系统操作日志`

系统参数会影响：

- 审核链
- 团号规则
- 利润统计口径
- 财务审核后是否允许修改
- 订单页显示字段

## 七、典型业务办理流程

## 1. 常规团队业务

1. 建客户、供应商、资源等基础资料
2. 建产品
3. 建团期
4. 生成团队
5. 录订单
6. 录游客名单
7. 建电子合同
8. 计调安排资源
9. 计调审核
10. 财务审核
11. 收款、付款、导游结算、返佣、发票
12. 看利润和统计

## 2. 散拼业务

1. 先建散拼产品和团期
2. 生成散拼团队
3. 不断往团队中挂订单
4. 实时看预控和实收
5. 接近发团时集中排资源
6. 发团后进入结算

## 3. 单项业务

1. 建单项业务团队
2. 录单项订单
3. 只安排对应资源
4. 审核和财务结算逻辑不变

## 八、哪些地方要重点控制

### 1. 团队和订单必须一致

要重点核对：

- 团号
- 出团日期
- 人数
- 客户
- 接送信息

### 2. 计调资源不能漏排

最容易漏的是：

- 导游
- 住宿
- 用车
- 景区
- 自费
- 购物
- 地接

### 3. 审核后不要随意改数据

特别是财务审核完成后，修改团队、费用、收付款都会影响利润和报表。

### 4. 银行现金账必须和收付款记录对应

否则系统里的流水和业务单据会脱节。

### 5. 参数配置不能随意改

因为它会影响整个系统的使用规则和统计口径。

## 九、老板怎么用这套系统

老板不需要每天深入所有录入页，建议重点看这几个区域：

1. 首页工作台  
看概况和提醒。

2. 团队管理 / 团队进度统计  
看团队推进情况。

3. 财务审核 / 财务收支进度  
看收入、成本、利润和回款付款进度。

4. 利润统计 / 报表中心  
看经营结果。

5. 系统参数 / 操作日志  
看规则是否被控制住、操作是否留痕。

## 十、使用结论

这套系统的正确理解是：

- 前端用来建产品、建团、下订单
- 中台用来排资源、做履约
- 后台用来审核、结算、做报表

它能解决的是旅行社/地接社“从接单到结算再到复盘”的整条业务链问题。

最重要的使用原则只有三条：

1. 先建基础资料，再做业务  
2. 围绕团队推进，不要绕开团队  
3. 审核和财务数据要严控，不要后改
