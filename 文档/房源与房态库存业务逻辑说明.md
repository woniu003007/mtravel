# 房源与房态库存业务逻辑说明

更新时间：2026-06-11

## 1. 模块定位

`计调操作 / 房源与房态库存` 只负责计调排房前的房源库存准备和锁房联动。

它不是采购资源管理，也不是酒店结算管理。

本模块的核心目标是：

- 让计调能看到某个酒店、某种房型、某天还有多少房。
- 让计调能先按房型数量锁房。
- 后续团队排房时，可以从这里扣减库存，并反查哪个团队占用了房。

## 2. 房源来源

当前只保留两类房源来源。

| 来源 | 含义 | 在哪里维护 |
| --- | --- | --- |
| 自营房源 | 甲方买断、包房、长期取得使用权的酒店或房源。 | `计调操作 / 房源与房态库存` |
| 资源采购房源 | 外部酒店资源，通过采购资源、供应商和采购关系形成。 | `采购管理 / 资源采购管理`、`采购关系管理` |

注意：

- 不再单独设计“临时外采房源”。
- 采购资源模块已经开发，不在房态库存模块里重复建设。
- 资源采购房源进入房态库存时，只引用采购关系和价格基础资料，不在本模块重新维护供应商、采购关系和采购价格。

## 3. 自营房源怎么维护

自营房源按三层维护。

### 3.1 自营酒店档案

酒店档案只维护酒店层信息，例如：

- 酒店名称
- 所在地
- 区域
- 地址
- 星钻标准
- 房源来源或酒店方
- 联系人
- 使用权有效期
- 启停状态

酒店档案不要因为有多个房型就重复录多条。

例如：

- `苏州园林假日酒店` 只录一条酒店档案。
- 标间、大床房、三人间放到房型管理里维护。

### 3.2 房型管理

一个自营酒店下面可以有多个房型。

房型层维护：

- 房型名称，例如标间、大床房、三人间。
- 床型。
- 可住人数。
- 采购价。
- 协议价。
- 价格单位。
- 房型状态。

价格放在房型层，不放在酒店档案层。

这样做的原因是：同一家酒店不同房型价格不同，后续排房和核算都需要按房型判断。

### 3.3 房号管理

房号是可选明细，不是锁房的前置条件。

房号层维护：

- 楼栋
- 楼层
- 房号
- 房型
- 床型
- 可住人数
- 房号状态

当前系统主逻辑是先按“房型数量”锁房。只有后续需要精细排到具体房号时，才使用房号明细。

## 4. 房态库存怎么维护

房态库存按以下维度维护：

```text
房源来源 + 酒店 + 房型 + 日期
```

每一天、每个房型维护四个核心数量：

| 数量 | 含义 |
| --- | --- |
| 总房量 | 当天这个房型总共有多少间可参与排房。 |
| 锁定量 | 已经被团队预锁，但还没最终入住或确认占用的数量。 |
| 占用量 | 已经确认被团队占用的数量。 |
| 剩余量 | 当前还能继续分配的数量。 |

计算口径：

```text
剩余量 = 总房量 - 锁定量 - 占用量
```

后续排房页面不要直接自己算库存，应该读取 `room_inventories` 的库存结果。

## 5. 锁房逻辑

锁房按房型数量锁定，不强制选择具体房号。

锁房时需要记录：

- 房源来源
- 酒店
- 房型
- 入住日期
- 退房日期
- 锁定数量
- 团队编号
- 团队名称
- 团队住宿标准

锁房成功后：

- 对应日期的 `锁定量` 增加。
- 对应日期的 `剩余量` 减少。
- 生成锁房流水。

如果库存不足：

- 不允许锁房成功。
- 后续页面应提示库存不足。

## 6. 占用和释放

后续团队排房确认后，锁房可以转为占用。

转占用后：

- `锁定量` 减少。
- `占用量` 增加。
- `剩余量` 不增加，因为房已经被团队实际占用。

释放锁房后：

- `锁定量` 减少。
- `剩余量` 增加。
- 锁房记录状态改为已释放。

## 7. 点击余量或占用量的逻辑

后续页面点击库存里的余量、锁定量或占用量时，应能反查相关团队。

依据是锁房流水：

- 哪个团队锁了房。
- 锁了哪个酒店。
- 锁了哪个房型。
- 锁了哪几天。
- 锁了多少间。
- 当前是已锁、已占用，还是已释放。

这就是老系统点击“余”能跳转看订单或团队占用的核心逻辑。

## 8. 与采购管理的边界

采购管理已经负责外部资源。

| 模块 | 负责内容 |
| --- | --- |
| `采购管理 / 资源采购管理` | 外部酒店、景区、餐厅、车队等资源主档。 |
| `采购管理 / 采购关系管理` | 外部资源和供应商的合作关系、负责人、电话、价格项目。 |
| `计调操作 / 房源与房态库存` | 把自营房源和资源采购房源转成按日期、房型可排的库存。 |

不要在房态库存里重复做采购资源、供应商和采购关系。

资源采购房源在房态库存中只做库存层处理：

- 来源类型为 `资源采购房源`。
- 来源 ID 指向采购关系。
- 可以维护某天某房型可用数量。
- 不维护具体房号。

## 9. 与后续排房模块的关系

后续开发 `团队安排 / 排房` 时，应按这个逻辑接入：

1. 团队产生住宿需求。
2. 按团队住宿标准、城市、日期、人数、房型查询房态库存。
3. 计调选择合适酒店和房型。
4. 系统锁定对应日期的房型数量。
5. 团队确认后，锁房转占用。
6. 取消或调整团队时，释放或调整库存。
7. 相关团队占用可从锁房流水反查。

排房模块不要另建一套库存逻辑。

## 10. 暂不在本模块处理的事情

以下内容不要放进当前房态库存模块：

- 酒店付款。
- 住宿成本结算。
- 财务审核。
- 供应商应付。
- 采购合同。
- 临时外采。
- 订单游客实际入住名单。

这些应在后续团队安排、成本、财务模块里处理。
